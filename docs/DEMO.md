# Демонстрационный сценарий и выступление

Для кого: тот, кто показывает сервис на питч-сессии или проверяет его сам.
Презентация — [presentation/DXA_QC_pitch.pptx](presentation/DXA_QC_pitch.pptx)
(редактируемый PowerPoint с заметками докладчика) и
[presentation/DXA_QC_pitch.pdf](presentation/DXA_QC_pitch.pdf); доклад по
слайдам с хронометражем и ответами на вопросы —
[presentation/DXA_QC_speech.docx](presentation/DXA_QC_speech.docx).
HTML-версия — `presentation/slides.html`, клавиша `F` — показ на весь экран.

## Подготовка (за 10 минут до показа)

```bash
./build.sh                                        # образ dxa-qc:1.0.0
python docs/presentation/make_demo_zip.py         # demo.zip, 7 исследований, 1.8 МБ
./run.sh                                          # http://localhost:8000
```

Проверка: страница открывается, в шапке зелёный индикатор «сервис работает»;
`curl localhost:8000/health` отвечает `"cnn_rotation": true, "cnn_artifacts": true`.

`demo.zip` собирается из обучающего набора по результатам сквозной оценки
(`service/evaluation.csv`): по одному исследованию на каждый тип нарушения,
где сервис и эксперт согласны, и два нормальных.

| исследование | что показывает |
|---|---|
| `2.25.125521310320333648427417313254965624364` | укладка позвоночника: гребни подвздошных костей не видны |
| `2.25.102755089973625799055786462646268820450` | ось позвоночника отклонена |
| `2.25.158646777318759504110695916200521633609` | посторонний предмет, тепловая карта сети |
| `2.25.114887542067602662452692698814728642117` | ротация бедра, тепловая карта сети на малом вертеле |
| `2.25.126293418391331346694592071563510265596` | недостаточный отступ области интереса бедра |
| `2.25.102965897799404973225419898683246248872` | норма |
| `2.25.105033841136787477881326326053319223817` | норма |

Снимки из обучающего набора: итоговые модели их видели. Честные метрики на
кадрах, которых модель не видела, — на слайде «Метрики качества» и в README.

## Показ, 3 минуты

1. **Загрузка (20 с).** Перетащить `demo.zip` в окно. Идёт прогресс по
   исследованиям, затем сводка: сколько снимков качественных, с нарушением, на
   ручной разбор. Сказать: «Всё считается в контейнере, снимки никуда не
   уходят; около двух секунд на исследование на процессоре».
2. **Ротация (40 с).** Щёлкнуть метку «Ротация». Справа — снимок бедра:
   голубым — найденные ориентиры, оранжевым — тепловая карта сети на малом
   вертеле. В карточке: вероятность нарушения по своду и порог, отдельно —
   выступ малого вертела в мм² и коридор нормы. Сказать: «Геометрия меряет
   выступ, сеть видит форму вертела, вердикт — их свод».
3. **Ось и укладка (30 с).** Клавиша `N` — следующий снимок с нарушением.
   Угол оси с порогом, зоны гребней. Сказать: «Каждое замечание — число с
   нормой, его можно проверить глазами».
4. **Отступы ROI (20 с).** Первая строка карточки — длина поля сканирования
   против нужных 12.9 см: по ней выносится вердикт, как у эксперта. Ниже —
   отступы по рисунку 6 ТЗ (3 см сверху и снизу, 2 см сбоку), на снимке —
   их линии; красная — не выдержана. Сказать: «Отступы по ТЗ видны всегда,
   режим строго по ТЗ — один флаг».
5. **Человек в контуре (30 с).** `A` — согласен, `D` — не согласен, `C` —
   комментарий. Кнопка «Мои отметки .csv»: «Это обратная связь для
   перекалибровки порогов в пилоте».
6. **Выгрузки (30 с).** «Таблица .xlsx» — восемь колонок ТЗ 2.5 в том же
   порядке, дальше вероятности и флаги. «DICOM SR .zip» — заключение
   по-русски, которое PACS покажет рядом со снимком.
7. **Пакетный режим (10 с, словами или в терминале).**
   `./run.sh batch /путь/к/исследованиям` → `out/report.xlsx`,
   `details.json`, `overlays.zip`, `sr.zip`.

Если показ вживую невозможен (нет Docker, проектор без сети) — те же шаги
на слайдах «Кейсы» и «Интерфейс и интеграция».

## Вопросы, которые стоит ждать

**Почему не одна сеть на всё?** На 6–36 нарушений на критерий ёмкую модель
учить не на чем, а вердикт сети оператор не проверит глазами. Геометрия там,
где критерий — измерение (ось, укладка, отступы); сеть там, где признак —
форма (ротация, посторонние предметы). Сеть проверяли и для ротации: одна
логистическая модель «вида кадра» дала ROC-AUC 0.50, ResNet-34 на полном
разрешении — 0.80.

**Чем подтверждено, что нет утечки?** Дедупликация по пикселям до разбиения,
фолды по исследованию, все пороги и свод — на обучающих фолдах. Честная
оценка пересчитывается одной командой: `python -m service.evaluate`, раздел
«честная оценка всего конвейера».

**Почему ROI судится по длине поля, а не по рисунку 6?** Так оценивает
эксперт: он ставит «норму» при 1.7–3.0 см под седалищной костью и «нарушение»
на коротких полях. Отступы по рисунку 6 мы меряем верно (с ручной разметкой
точек вердикт совпадает на 147 кадрах из 147), но с экспертом они совпадают на
F1 0.35, а длина поля — на 0.71. По меткам ничего не подбиралось: 30 мм — из
ТЗ, 69 мм от вертела до седалищной кости — медиана анатомии. Режим строго по
ТЗ — `--roi-rule margins`; расхождения перечислены в `DATASET.md`.

**Почему ось срабатывает лишний раз?** При сколиозе эксперт нарушение оси не
ставит (14 кадров из 14), а сервис по углу — может. Отличить сколиоз от наклона
по поясничному отделу не удалось, сеть на оси сигнала не дала (ROC-AUC 0.51).

**Что будет на другом аппарате?** Масштаб задан константой (в данных нет
`PixelSpacing`), его нужно перепроверить; сеть и пороги дообучаются теми же
скриптами (`docs/TRAINING.md`). Для сети яркость нормализуется по перцентилям —
12-битный снимок не сломает вход.

**Сколько стоит внедрение?** Один контейнер на CPU, 2–4 ядра и 4 ГБ памяти.
GPU не нужен. Интеграция — DICOM-роутер в PACS и DICOM SR обратно.

## Заметки к слайдам

Полный текст выступления по слайдам — в `presentation/DXA_QC_speech.docx`
(там же миниатюры слайдов, хронометраж и ответы на вопросы) и в заметках
докладчика `presentation/DXA_QC_pitch.pptx`. Регламент: 19 слайдов, около 9 минут,
затем демонстрация.

Пересобрать презентацию после переобучения:

```bash
python -m service.evaluate                                   # service/metrics.json
python -m service.evaluate --no-cnn --out runs/eval_geometry/metrics.json
python -m service.evaluate --no-cnn --roi-rule margins --out runs/eval_baseline/metrics.json
python -m service.benchmark                                  # service/benchmark.json
python docs/presentation/make_demo_zip.py
python docs/presentation/build.py --cases --screens demo.zip # HTML, PPTX, PDF, DOCX
```
