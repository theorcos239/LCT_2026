# Демонстрационный сценарий и выступление

Для кого: тот, кто показывает сервис на питч-сессии или проверяет его сам.
Презентацию (редактируемый PowerPoint с заметками докладчика и PDF) и доклад
по слайдам с хронометражем и ответами на вопросы команда передаёт отдельно:
в них есть снимки DXA, поэтому в репозитории их нет. Презентация сделана по
шаблону ЛЦТ 2026: обязательные слайды о команде в начале, дальше — решение.

## Подготовка (за 10 минут до показа)

```bash
./build.sh                                        # образ dxa-qc:1.0.0
./run.sh                                          # http://localhost:8000
```

Проверка: страница открывается, в шапке зелёный индикатор «сервис работает»;
`curl localhost:8000/health` отвечает `"cnn_rotation": true, "cnn_artifacts": true`.

Без Docker — настольное приложение: «Контроль качества DXA» из меню «Пуск»
([DESKTOP.md](DESKTOP.md)), дальше всё так же. Для шага с ботом — бот
запущен (`python -m bot` или `bot\run_bot.ps1`), `demo.zip` лежит в корне
рабочей папки, в Telegram открыт [@LCT_bone_density_research_bot](https://t.me/LCT_bone_density_research_bot).

Демонстрационный архив `demo.zip` (7 исследований, 1.8 МБ) команда готовит
заранее; в репозиторий он не входит, потому что содержит снимки. Архив
собирается из обучающего набора по результатам сквозной оценки
(`service/evaluation.csv`): по одному исследованию на каждый тип нарушения,
где сервис и эксперт согласны, и два нормальных.

| исследование | что показывает |

| `2.25.126293418391331346694592071563510265596` | недостаточный отступ области интереса бедра |

## Показ, 3 минуты

1. **Загрузка (20 с).** Перетащить `demo.zip` в окно. Идёт прогресс по
   исследованиям, затем сводка: сколько снимков качественных, с нарушением, на
   ручной разбор. Сказать: «Всё считается на этом компьютере (в контейнере
   или в установленном приложении), снимки никуда не уходят; около двух
   секунд на исследование на процессоре».
2. **Ротация (40 с).** Щёлкнуть метку «Ротация». Справа — снимок бедра:
   голубым — найденные ориентиры, оранжевым — тепловая карта нейросети на
   малом вертеле (костном выступе на внутренней стороне бедра). В карточке:
   вероятность нарушения по объединённой оценке нейросети и измерения и
   порог, отдельно — выступ малого вертела в мм² и коридор нормы. Сказать:
   «Измерение меряет выступ вертела, нейросеть видит его форму, вердикт — их
   объединённая оценка».
3. **Ось и укладка (30 с).** Клавиша `N` — следующий снимок с нарушением.
   Угол оси с порогом, зоны гребней. Сказать: «Каждое замечание — число с
   нормой, его можно проверить глазами».
4. **Отступы ROI (20 с).** Первая строка карточки — длина поля сканирования
   против нужных 12.9 см: по ней выносится вердикт, как у эксперта. Ниже —
   отступы по рисунку 6 ТЗ (3 см сверху и снизу, 2 см сбоку), на снимке —
   их линии; красная — не выдержана. Сказать: «Отступы по ТЗ видны всегда;
   если эталон размечен дословно по ТЗ, этот режим включается одним
   параметром запуска».
5. **Человек в контуре (30 с).** `A` — согласен, `D` — не согласен, `C` —
   комментарий. Кнопка «Мои отметки .csv»: «Это обратная связь: по этим
   отметкам пороги подстраиваются под аппарат клиники во время пилота».
6. **Выгрузки (30 с).** «Таблица .xlsx» — восемь колонок ТЗ 2.5 в том же
   порядке, дальше вероятности и флаги. «DICOM SR .zip» — структурированное
   текстовое заключение по-русски, которое PACS (архив снимков клиники)
   покажет рядом со снимком.
7. **Пакетный режим (10 с, словами или в терминале).**
   `./run.sh batch /путь/к/исследованиям` → `out/report.xlsx`,
   `details.json`, `overlays.zip`, `sr.zip`.
8. **Бонус: Telegram-бот (20 с, по желанию).** Телефон с ботом: `/demo` — через
   несколько секунд сводка по семи исследованиям, альбом снимков с разметкой и
   таблица. Сказать: «Тот же конвейер во всех четырёх интерфейсах —
   веб-интерфейс, настольное приложение, командная строка и бот; отчёты у них
   совпадают побитово. Приложение работает полностью локально, снимки не
   покидают компьютер. Бот — приятный бонус, а не обязательная часть проекта:
   демонстрация альтернативного интерфейса, тот же
   анализ отвечает в чате, с телефона; это заготовка для интеграции в другие
   сервисы — мессенджер медорганизации, МИС, уведомления. Для реальных данных
   пациентов он не предназначен: файлы проходят через серверы Telegram».

Если показ вживую невозможен (нет Docker, проектор без интернета) — те же шаги
на слайдах «Кейсы» и «Интерфейсы».

## Вопросы, которые стоит ждать

**Почему не одна нейросеть на всё?** На 6–36 нарушений на критерий ёмкую
модель учить не на чем, а вердикт нейросети оператор не проверит глазами.
Геометрия там, где критерий — измерение (ось, укладка, отступы); нейросеть
там, где признак — форма (ротация, посторонние предметы). Нейросеть проверяли
и для ротации: одна логистическая модель «вида кадра» дала ROC-AUC 0.50
(наугад), ResNet-34 на полном разрешении — 0.80.

**Чем подтверждено, что нет утечки?** Дедупликация по пикселям до разбиения,
деление на пять частей (фолдов) по исследованиям, все пороги и объединённая
оценка нейросети и измерения подобраны только на обучающих частях. Честная
оценка пересчитывается одной командой: `python -m service.evaluate`, раздел
«честная оценка всего конвейера».

**Почему ROI судится по длине поля, а не по рисунку 6?** Так оценивает
эксперт: он ставит «норму» при 1.7–3.0 см под седалищной костью и «нарушение»
на коротких полях. Отступы по рисунку 6 мы меряем верно (с ручной разметкой
точек вердикт совпадает на 147 кадрах из 147), но с экспертом они совпадают на
F1 0.35, а длина поля — на 0.71. По меткам ничего не подбиралось: 30 мм — из
ТЗ, 69 мм от вертела до седалищной кости — медиана анатомии. Режим строго по
ТЗ — `--roi-rule margins`; расхождения перечислены в `DATASET.md`.

**Почему ось срабатывает лишний раз?** При сколиозе эксперт нарушение оси не
ставит (14 кадров из 14), а сервис по углу — может. Отличить сколиоз от наклона
по поясничному отделу не удалось, нейросеть на оси сигнала не дала
(ROC-AUC 0.51).

**Что будет на другом аппарате?** Масштаб задан константой (в данных нет
`PixelSpacing`), его нужно перепроверить; нейросеть и пороги дообучаются теми
же скриптами (`docs/TRAINING.md`). Для нейросети яркость нормализуется по
перцентилям — 12-битный снимок не сломает вход.

**Сколько стоит внедрение?** Один контейнер на CPU, 2–4 ядра и 4 ГБ памяти.
GPU не нужен. Интеграция — снимки приходят из PACS через DICOM-роутер,
заключение DICOM SR уходит обратно в PACS.

## Заметки к слайдам

Полный текст выступления по слайдам — в докладе `DXA_QC_speech.docx`
(там же миниатюры слайдов, хронометраж и ответы на вопросы) и в заметках
докладчика презентации; оба файла команда передаёт отдельно. Регламент: 26 слайдов, около 12 минут при спокойном темпе
(если регламент короче — бегло слайды 13, 16 и 22), затем демонстрация.

Числа на слайдах берутся из тех же файлов метрик, что и в README. После
переобучения метрики пересчитываются так:

```bash
python -m service.evaluate                                   # service/metrics.json
python -m service.evaluate --no-cnn --out runs/eval_geometry/metrics.json
python -m service.evaluate --no-cnn --roi-rule margins --out runs/eval_baseline/metrics.json
python -m service.benchmark                                  # service/benchmark.json
```
