# Руководство по развёртыванию

Для кого: инженер, который поднимает сервис на Linux-сервере или проверочном
стенде. Что сервис делает — в [USER_GUIDE.md](USER_GUIDE.md).

## Требования

| | минимум | рекомендуется |
|---|---|---|
| CPU | 2 ядра x86-64 | 4 ядра |
| RAM | 2 ГБ | 4 ГБ |
| диск | 1 ГБ (образ 162 МБ + временные задания) | + место под отчёты |
| GPU | не нужен | не нужен |
| ПО | Docker 20+, POSIX sh | — |
| сеть | не нужна после сборки образа | — |

На целевой конфигурации ТЗ (2×H200) сервис использует только CPU. Скорость:
~30 мс на снимок, исследование из трёх снимков ~0.1 с при лимите ТЗ 3 минуты.

## Сборка

```bash
./build.sh                          # образ dxa-qc:1.0.0 и dxa-qc:latest
IMAGE=registry/dxa TAG=dev ./build.sh
```

`build.sh` сначала проверяет, что веса моделей лежат в репозитории
(`region_clf/model.joblib`, `spine_qc/model.joblib`,
`spine_qc/thresholds.json`, `hip_rotation/thresholds.json`), и не соберёт
образ без них — иначе сервис поднялся бы, но молча потерял критерии.

Воспроизводимость сборки: базовый образ закреплён дайджестом
(`FROM python:3.11-slim@sha256:…`), все Python-зависимости — точными
версиями в `requirements.txt`. Сборке нужен доступ к Docker Hub и PyPI;
дальше сеть не используется.

Обновить базовый образ (например, ради патчей безопасности):

```bash
docker pull python:3.11-slim
docker inspect --format='{{index .RepoDigests 0}}' python:3.11-slim
# подставить результат в строку FROM в Dockerfile, пересобрать, прогнать тесты
```

### Перенос на машину без интернета

```bash
docker save dxa-qc:1.0.0 | gzip > dxa-qc-1.0.0.tar.gz     # на машине со сборкой
docker load < dxa-qc-1.0.0.tar.gz                          # на целевой машине
```

## Запуск

### HTTP API

```bash
./run.sh                   # http://localhost:8000
PORT=9000 ./run.sh         # другой порт
```

Эквивалент без скрипта:

```bash
docker run -d --name dxa-qc -p 8000:8000 --restart unless-stopped dxa-qc:1.0.0
```

Проверка: `curl http://localhost:8000/health` →
`{"status": "ok", "models": {...: true}}`. В образ встроен `HEALTHCHECK`
на этот же эндпоинт — `docker ps` покажет `healthy`.

### Пакетная обработка без API

```bash
./run.sh batch /путь/к/исследованиям          # результат в ./out
OUT=/srv/reports FMT=csv ./run.sh batch /data  # другой каталог и формат
```

В `./out` появятся `report.xlsx`, `details.json`, `overlays.zip`, `sr.zip`.
Эквивалент без скрипта:

```bash
docker run --rm --user "$(id -u):$(id -g)" \
    -v /путь/к/исследованиям:/data:ro -v "$PWD/out":/out dxa-qc:1.0.0 \
    python -m service.cli /data --out /out/report.xlsx \
        --details /out/details.json --overlays /out/overlays.zip --sr /out/sr.zip
```

### Переменные

| переменная | где | по умолчанию | смысл |
|---|---|---|---|
| `PORT` | run.sh | 8000 | порт API на хосте |
| `OUT` | run.sh batch | `./out` | каталог результатов |
| `FMT` | run.sh batch | `xlsx` | `xlsx` или `csv` |
| `IMAGE`, `TAG` | build.sh, run.sh | `dxa-qc`, `1.0.0` | имя образа |
| `DXA_QC_KEYPOINTS` | контейнер/процесс API | выключено | `1` — включить модель ключевых точек (нужны torch и веса, см. ниже) |
| `OMP_NUM_THREADS` и др. | Dockerfile | 1 | один поток BLAS — условие воспроизводимости, не менять |

## Безопасность и данные

- **Данные монтируются только на чтение** (`:ro`) — сервис не изменяет
  исходные DICOM.
- **Ни один эндпоинт не обращается в сеть**, снимки не покидают контейнер.
- Процесс в контейнере работает от непривилегированного пользователя
  `dxa` (uid 10001), не root. `run.sh batch` запускает контейнер от uid/gid
  вызывающего (`--user`): иначе на Linux uid 10001 не смог бы писать в
  созданный пользователем `./out`, а результаты принадлежали бы чужому uid.
  При ручном `docker run` с каталогом результатов добавляйте то же самое.
- Загружаемые zip проверяются на path traversal (`../` в именах).
- Аутентификации в API нет: сервис рассчитан на закрытый контур. Для доступа
  из сети его нужно закрыть reverse-proxy с авторизацией (nginx, Traefik) и
  TLS.

## Эксплуатация

- **Задания пакетной обработки хранятся в памяти процесса** и в
  `/tmp/dxa_qc_jobs` внутри контейнера. Перезапуск контейнера их теряет, а
  файлы сами не удаляются — при длительной работе чистить `/tmp/dxa_qc_jobs`
  или периодически перезапускать контейнер. Для большой пачки надёжнее
  `./run.sh batch`, чем API.
- **Масштабирование** — процессами, а не потоками: несколько контейнеров за
  балансировщиком или несколько `run.sh batch` на разных подмножествах
  исследований. Один процесс держит один поток намеренно (воспроизводимость).
- **Логи** — stdout контейнера (`docker logs dxa-qc`).

## Модель ключевых точек (необязательно)

По умолчанию выключена и в базовый образ не входит: на обучающей выборке
модель пока не выигрывает у контурной геометрии (README, «Модель ключевых
точек»), а torch увеличивает образ вдвое. Для эксперимента есть отдельный
вариант образа — `Dockerfile.keypoints`: базовый образ плюс torch/torchvision
в CPU-сборке (368 МБ против 162). Веса (`runs/keypoints`, 187 МБ) в образ не
кладутся и монтируются снаружи:

```bash
./build.sh                                             # сначала базовый образ
docker build -f Dockerfile.keypoints -t dxa-qc:keypoints .
docker run -p 8000:8000 -v "$PWD/runs:/app/runs:ro" dxa-qc:keypoints
```

В этом образе `DXA_QC_KEYPOINTS=1` уже выставлена. Первый запрос идёт
~3 с (загрузка двух фолдов), дальше ~0.6 с на снимок — в 20 раз медленнее
контурной геометрии, но в пределах лимита ТЗ. Если веса не смонтированы,
сервис не падает: снимки считаются контурной геометрией, а причина
попадает во флаг `keypoints:unavailable(...)`.

## Проверка после развёртывания

```bash
curl -s localhost:8000/health
curl -s localhost:8000/version            # пороги и версии моделей
curl -s -F file=@снимок.dcm localhost:8000/analyze
```

Полный набор тестов (нужен обучающий набор рядом с кодом, вне образа):

```bash
python -m service.test_service            # формат, устойчивость, API, SR, детерминизм
python -m region_clf.test_region_clf
python -m hip_roi.test_hip_roi
```

## Удаление

```bash
docker rm -f dxa-qc
docker rmi dxa-qc:1.0.0 dxa-qc:latest
```
