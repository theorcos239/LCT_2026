# Обучение и дообучение

Для кого: разработчик, который переобучает модели на новых данных или
переносит сервис на другой денситометр. Почему модели устроены именно так —
в [README.md](../README.md), разделы «Как устроено решение» и «Модель
ключевых точек».

## Что обучается

Рабочий контур — классическая геометрия, две маленькие линейные модели и
сверточная сеть `cnn_qc` для ротации бедра и посторонних предметов.
Калибровка геометрии и линейных моделей — около минуты на ноутбуке без GPU;
сеть — около 6 минут на критерий на GPU (на CPU — дольше, но тоже можно).

| модуль | что учится | артефакты (в git) |
|---|---|---|
| `region_clf` | классификатор области lh / rh / spine + фильтр «не DXA» | `region_clf/model.joblib`, `metrics.json` |
| `spine_qc` | пороги трёх критериев позвоночника + модель «вида кадра» (вторая оценка) | `spine_qc/model.joblib`, `thresholds.json`, `metrics.json`, `measurements.csv` |
| `hip_rotation` | коридор нормы выступа малого вертела, вероятность (Платт) | `hip_rotation/thresholds.json`, `metrics.json`, `measurements.csv` |
| `hip_roi` | пороги 3/3/2 см взяты из ТЗ, нужная длина поля 12.9 см — из ТЗ и медианы анатомии; учится только вероятность (Платт по недобору длины поля и, отдельно, по недобору отступа) | `hip_roi/probability.json` — оба правила; `hip_roi/eval/` — сверка с экспертом |
| `cnn_qc` | ResNet-34, ансамбль 3 сидов на критерий, свод с геометрией и порог (torch, onnx); сеть посторонних предметов стартует с энкодера модели ключевых точек | `cnn_qc/<критерий>/model_{0,1,2}.onnx`, `meta.json`, `oof.csv` |
| `src/dxa_qc` | модель ключевых точек (необязательная, torch) | `runs/keypoints/` — вне git |

## Данные

```
НД_для_обучения/
├── Исследования/<папка исследования>/…/*.dcm     снимки
└── разметка.xlsx                                  метки эксперта на исследование
region_clf/labels.csv                              область каждого уникального кадра
folds.csv                                          5 фолдов, группа — исследование
```

- Метки эксперта заданы **на исследование и область** («правое бедро,
  ротация»); `trainset.py` раскладывает их на кадры. Все модули берут выборку
  через `trainset.frames()` — одни и те же 252 кадра и одно разбиение.
- Дубликаты (Lunar сохраняет снимок по нескольку раз) схлопываются по MD5
  пикселей: 499 файлов → 252 уникальных кадра.
- **`folds.csv` фиксирован и только читается.** Группа — исследование (два
  бедра одного пациента не должны разойтись по фолдам — это утечка), страта —
  самое редкое нарушение в исследовании. При добавлении исследований новые
  получают фолд, старые свой сохраняют — иначе новые метрики несравнимы со
  старыми.

## Порядок запуска

```bash
python -m pip install -r requirements.txt

python -m region_clf.make_labels      # 1. эталон области (labels.csv)
python -m region_clf.train --stress   # 2. классификатор области + стресс-тест
python -m spine_qc.calibrate --sweep  # 3. пороги позвоночника, OOF-метрики
python -m hip_rotation.calibrate      # 4. коридор нормы ротации
python -m hip_roi.evaluate            # 5. сверка ROI бедра с экспертом
python -m hip_roi.probability         #    вероятность нарушения ROI: длина поля и рисунок 6
python -m pip install -r requirements-train.txt  # torch, onnx — только для шага 6
python -m cnn_qc.train --criterion rotation      # 6. сеть: OOF, свод, ансамбль, ONNX
python -m cnn_qc.train --criterion artifacts --init keypoints   # нужны runs/keypoints/fold0..4.pt
python -m service.evaluate            # 7. сквозные метрики с 95% ДИ + честная оценка
python -m service.evaluate --no-cnn --out runs/eval_geometry/metrics.json
python -m service.evaluate --no-cnn --roi-rule margins --out runs/eval_baseline/metrics.json
python -m service.benchmark           #    скорость на всех исследованиях
```

Сеть посторонних предметов стартует с энкодера модели ключевых точек
(`--init keypoints`): для фолда k — модели, обученной без фолда k. Веса
`runs/keypoints/fold*.pt` лежат вне git, поэтому сначала обучите модель точек
(раздел ниже). Без них — `--init imagenet`: прежняя поставка, свод ROC-AUC 0.82
против 0.85.

Поставленная сеть предметов обучена от энкодера **предыдущей версии** модели
точек (5 фолдов, удалена при замене на модель, которая не выдумывает точки).
ONNX сети от весов модели точек не зависят и работают как есть, но
воспроизвести их нельзя: у текущей модели обучены фолды 0–1, и это другие
веса. `--init keypoints` без всех пяти фолдов останавливается с сообщением
(подменять недостающий фолд чужим нельзя — это утечка в OOF); после
дообучения фолдов 2–4 сеть можно переобучить, и её цифры изменятся.

Шаги 2–5 независимы друг от друга; шаг 6 читает измерения шагов 3–4
(`spine_qc/measurements.csv`, `hip_rotation/measurements.csv`) — свод сети
строится поверх них; шаг 7 — итог по всему конвейеру. Если меняются только
измерения, а сеть переучивать не нужно, `python -m cnn_qc.train --criterion
rotation --calibrate-only` пересчитает свод и порог по сохранённым
OOF-вероятностям сети за секунды. У
калибровок есть `--no-save`: посчитать метрики, не трогая закоммиченные
пороги. Прогон детерминирован — на тех же данных результаты совпадают
побайтно, кроме колонок со временем.

Каждый калибратор печатает **out-of-fold** метрики: порог и модель учатся
только на обучающих фолдах, метрика считается на отложенном. У сети оценка
вложенная: и сеть, и свод, и порог не видели отложенный фолд. Сводная честная
оценка всего конвейера — раздел «честная оценка» в выводе `service.evaluate`
(`honest_oof` в `service/metrics.json`). Ориентироваться надо на неё, а не на
метрики по всей выборке — те завышены, потому что пороги подобраны на тех же
данных (разница показана в README).

Обучение сети детерминировано: сиды, детерминированные алгоритмы cuDNN,
фиксированный порядок кадров. На другой видеокарте веса могут отличаться в
последних знаках — поэтому поставляются готовые ONNX-файлы, а не рецепт.

После обучения:

```bash
python -m service.test_service        # формат, устойчивость, детерминизм, API, SR
./build.sh                            # образ соберётся только при наличии весов
```

## Дообучение на новых данных

1. Положить новые исследования в `НД_для_обучения/Исследования/`, добавить
   строки в `разметка.xlsx` в том же формате.
2. Дописать новые исследования в `folds.csv`, **не меняя фолды старых** —
   тем же правилом (группа — исследование, страта — редчайшее нарушение;
   порядок редкости и стратификация — `src/dxa_qc/folds.py`).
3. `python -m region_clf.make_labels` — эвристика предложит области новых
   кадров; их стоит проверить глазами (так сделано для исходных 252).
4. Шаги 2–7 из списка выше. Сравнить OOF-метрики с прежними
   (`*/metrics.json` в git): при нескольких положительных примерах на
   критерий разница в пределах доверительного интервала — шум.

### Другой денситометр

Все 100 исследований обучающего набора — GE Lunar Prodigy Advance, и
масштаб задан константой (`PixelSpacing` в этих файлах пуст): 0.600 мм/px
для позвоночника (`spine_qc/geometry.py`), 0.607 — для бедра
(`hip_roi/geometry.py`, `MM_PER_PX`). Для другого аппарата:

1. Проверить масштаб по анатомии: шаг «позвонок + диск» в поясничном отделе
   27–36 мм (так константа и выведена, см. DATASET.md).
2. Поправить константы, прогнать шаги 2–7: пороги критериев в миллиметрах и
   градусах переносятся, коридор ротации, модели «вида кадра» и сеть — нет.
   Сети яркость нормализуется по перцентилям, 12-битный вход её не сломает,
   но другой вид снимка требует дообучения на снимках нового аппарата.
3. Отдельно смотреть на `region_clf`: фильтр «не DXA» учился на одном
   аппарате и может отбраковывать чужие снимки — проверить долю
   `undetermined` на новых данных.

## Модель ключевых точек (необязательно)

U-Net с энкодером ResNet-34, 29 каналов (21 точка позвоночника, 8 бедра).
По умолчанию в сервисе выключена, подключается флагом `--keypoints`. Нужен
torch:

```bash
python -m pip install -r requirements-train.txt
```

Код лежит в `src/` и пакетом не ставится, поэтому модули запускаются с
`PYTHONPATH=src` из корня репозитория:

```bash
# разметка (JSON из инструмента разметки) + DICOM -> один npz
PYTHONPATH=src python -m dxa_qc.pack \
    --annotations data/*.json \
    --html Processing/razmetka_all.html \
    --studies НД_для_обучения/Исследования \
    --out data/keypoints.npz

# обучение по фолдам из folds.csv, веса в runs/keypoints
PYTHONPATH=src python -m dxa_qc.train --config configs/keypoints.yaml
```

- Все гиперпараметры — в `configs/keypoints.yaml`, любой переопределяется из
  командной строки: `--set train.epochs=50 train.batch_size=8`. Копия
  итогового конфига сохраняется рядом с весами.
- Фолды — `train.folds` (по умолчанию все пять; сейчас обучены 0 и 1).
  Готовые фолды (есть `oof_fold{N}.npz`) пропускаются, прерванный
  продолжается с чекпоинта `fold{N}_last.pt`; `--no-resume` — начать заново.
  Досрочная остановка: прервать процесс и запустить с `--finalize` — обучение
  не продолжается, у недоученного фолда берутся лучшие веса `fold{N}.pt`,
  необученные фолды в прогон не входят, пороги и метрики собираются по тому,
  что есть. Так собран текущий прогон: фолд 0 — 600 эпох, фолд 1 остановлен
  на 329-й (лучшие эпохи 279 и 318; дальше медиана не улучшалась).
- Нужен GPU: на CPU эпоха ~48 с (600 эпох — 8 ч на фолд), на RTX 5090 — 2.3 с
  (~23 мин на фолд). На Windows воркеры DataLoader держатся постоянными,
  подготовка кадра стоит ~3 мс, так что `--set train.num_workers=0` почти не
  медленнее.
- В ансамбль сервиса идут `fold{N}.pt` (лучшая эпоха) всех фолдов, найденных
  в `runs/keypoints`; `_last.pt` — только для продолжения обучения.
- Против выдуманных точек: видимость при аугментации решается по пикселям
  снимка, а не по холсту; край кадра обрезается (`augment.p_crop`, часть
  обрезов — вплотную к точке), чтобы у модели были примеры «структуры нет в
  кадре»; на отложенном фолде каждый кадр дополнительно оценивается в 6
  обрезанных вариантах (`eval.crops_per_image`), где видимость известна точно.
- Пороги видимости и все метрики считаются на **рабочем инференсе**
  (`Predictor`: TTA, маска заполнения, согласованная расшифровка
  позвоночника): TTA снижает высоту пиков, и порог одиночного прохода в
  сервисе терял видимые точки. Порог — максимум (TPR + TNR) / 2 на исходных и
  обрезанных кадрах (`infer.threshold_objective: balanced`); где отсутствующих
  примеров нет, он теряет не больше 2 % видимых.
- На выходе: `metrics_per_point.csv` (медиана/p90 ошибки в мм, PCK, F1
  видимости по каждой точке), `metrics_end_to_end.csv` (ошибка угла оси,
  отступов ROI и выступа малого вертела против геометрии по разметке
  эксперта), `metrics_visibility.csv` (доля выдуманных и потерянных точек),
  `thresholds.csv` (пороги видимости).

Честная оценка прогона — каждый фолд своими весами на своих отложенных
кадрах, порог видимости подобран на остальных фолдах; `--calibrate`
пересчитывает `thresholds.csv` без переобучения:

```bash
PYTHONPATH=src python -m dxa_qc.evaluate --run runs/keypoints --out runs/keypoints
PYTHONPATH=src python -m dxa_qc.test_dxa_qc     # тесты: видимость, обрезание, декод, цепочка
```

Сравнить модель с контурной геометрией честно — каждый кадр считает модель
фолда, который его не видел; пока обучены фолды 0–1, только на их кадрах:

```bash
python -m service.evaluate --keypoints-oof --folds 0 1 --no-cnn --roi-rule margins     --out runs/eval_keypoints/metrics.json
```

Разбор этого сравнения и условия, при которых модель стоит включить по
умолчанию, — в README, «Модель ключевых точек». Коротко: на кадрах фолдов
0–1 модель уже не проигрывает контуру (macro-F1 0.571 против 0.541), но
нарушений оси там четыре, а фолды 2–4 не обучены.
