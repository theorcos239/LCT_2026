# Обучение и дообучение

Для кого: разработчик, который переобучает модели на новых данных или
переносит сервис на другой денситометр. Почему модели устроены именно так —
в [README.md](../README.md), разделы «Как устроено решение» и «Модель
ключевых точек».

## Что обучается

Рабочий контур — классическая геометрия плюс две маленькие линейные модели.
Обучение всего контура занимает около минуты на ноутбуке, GPU не нужен.

| модуль | что учится | артефакты (в git) |
|---|---|---|
| `region_clf` | классификатор области lh / rh / spine + фильтр «не DXA» | `region_clf/model.joblib`, `metrics.json` |
| `spine_qc` | пороги трёх критериев позвоночника + модель «вида кадра» (вторая оценка) | `spine_qc/model.joblib`, `thresholds.json`, `metrics.json`, `measurements.csv` |
| `hip_rotation` | коридор нормы выступа малого вертела | `hip_rotation/thresholds.json`, `metrics.json`, `measurements.csv` |
| `hip_roi` | ничего: пороги 3/3/2 см взяты из ТЗ | `hip_roi/eval/` — только сверка с экспертом |
| `src/dxa_qc` | модель ключевых точек (необязательная, torch) | `runs/keypoints/` — вне git |

## Данные

```
НД_для_обучения/
├── Исследования/<папка исследования>/…/*.dcm     снимки
└── разметка.xlsx                                  метки эксперта на исследование
region_clf/labels.csv                              область каждого уникального кадра
folds.csv                                          5 фолдов, группа — исследование
```

- Метки эксперта заданы **на исследование и область** («правое бедро,
  ротация»); `trainset.py` раскладывает их на кадры. Все модули берут выборку
  через `trainset.frames()` — одни и те же 252 кадра и одно разбиение.
- Дубликаты (Lunar сохраняет снимок по нескольку раз) схлопываются по MD5
  пикселей: 499 файлов → 252 уникальных кадра.
- **`folds.csv` фиксирован и только читается.** Группа — исследование (два
  бедра одного пациента не должны разойтись по фолдам — это утечка), страта —
  самое редкое нарушение в исследовании. При добавлении исследований новые
  получают фолд, старые свой сохраняют — иначе новые метрики несравнимы со
  старыми.

## Порядок запуска

```bash
python -m pip install -r requirements.txt

python -m region_clf.make_labels      # 1. эталон области (labels.csv)
python -m region_clf.train --stress   # 2. классификатор области + стресс-тест
python -m spine_qc.calibrate --sweep  # 3. пороги позвоночника, OOF-метрики
python -m hip_rotation.calibrate      # 4. коридор нормы ротации
python -m hip_roi.evaluate            # 5. сверка ROI бедра с экспертом
python -m service.evaluate            # 6. сквозные метрики с 95% ДИ
```

Шаги 2–4 независимы друг от друга, шаг 6 — итог по всему конвейеру. У
калибровок есть `--no-save`: посчитать метрики, не трогая закоммиченные
пороги. Прогон детерминирован — на тех же данных результаты совпадают
побайтно, кроме колонок со временем.

Каждый калибратор печатает **out-of-fold** метрики: порог и модель учатся
только на обучающих фолдах, метрика считается на отложенном. Ориентироваться
надо на них, а не на метрики по всей выборке из `service.evaluate` — те
завышены, потому что пороги подобраны на тех же данных (разница показана в
README).

После обучения:

```bash
python -m service.test_service        # формат, устойчивость, детерминизм, API, SR
./build.sh                            # образ соберётся только при наличии весов
```

## Дообучение на новых данных

1. Положить новые исследования в `НД_для_обучения/Исследования/`, добавить
   строки в `разметка.xlsx` в том же формате.
2. Дописать новые исследования в `folds.csv`, **не меняя фолды старых** —
   тем же правилом (группа — исследование, страта — редчайшее нарушение;
   порядок редкости и стратификация — `src/dxa_qc/folds.py`).
3. `python -m region_clf.make_labels` — эвристика предложит области новых
   кадров; их стоит проверить глазами (так сделано для исходных 252).
4. Шаги 2–6 из списка выше. Сравнить OOF-метрики с прежними
   (`*/metrics.json` в git): при нескольких положительных примерах на
   критерий разница в пределах доверительного интервала — шум.

### Другой денситометр

Все 100 исследований обучающего набора — GE Lunar Prodigy Advance, и
масштаб задан константой (`PixelSpacing` в этих файлах пуст): 0.600 мм/px
для позвоночника (`spine_qc/geometry.py`), 0.607 — для бедра
(`hip_roi/geometry.py`, `MM_PER_PX`). Для другого аппарата:

1. Проверить масштаб по анатомии: шаг «позвонок + диск» в поясничном отделе
   27–36 мм (так константа и выведена, см. DATASET.md).
2. Поправить константы, прогнать шаги 2–6: пороги критериев в миллиметрах и
   градусах переносятся, коридор ротации и модели «вида кадра» — нет.
3. Отдельно смотреть на `region_clf`: фильтр «не DXA» учился на одном
   аппарате и может отбраковывать чужие снимки — проверить долю
   `undetermined` на новых данных.

## Модель ключевых точек (необязательно)

U-Net с энкодером ResNet-34, 29 каналов (21 точка позвоночника, 8 бедра).
По умолчанию в сервисе выключена, подключается флагом `--keypoints`. Нужен
torch:

```bash
python -m pip install -r requirements-train.txt
```

Код лежит в `src/` и пакетом не ставится, поэтому модули запускаются с
`PYTHONPATH=src` из корня репозитория:

```bash
# разметка (JSON из инструмента разметки) + DICOM -> один npz
PYTHONPATH=src python -m dxa_qc.pack \
    --annotations data/*.json \
    --html Processing/razmetka_all.html \
    --studies НД_для_обучения/Исследования \
    --out data/keypoints.npz

# обучение по фолдам из folds.csv, веса в runs/keypoints
PYTHONPATH=src python -m dxa_qc.train --config configs/keypoints.yaml
```

- Все гиперпараметры — в `configs/keypoints.yaml`, любой переопределяется из
  командной строки: `--set train.epochs=50 train.batch_size=8`. Копия
  итогового конфига сохраняется рядом с весами.
- Фолды — `train.folds` (по умолчанию все пять; обучены все). Готовые фолды
  (есть `oof_fold{N}.npz`) пропускаются, прерванный продолжается с чекпоинта
  `fold{N}_last.pt`; `--no-resume` — начать заново.
- Нужен GPU: на CPU эпоха ~48 с (600 эпох — 8 ч на фолд), на RTX 5090 — 2.3 с
  (~23 мин на фолд). На Windows воркеры DataLoader держатся постоянными,
  подготовка кадра стоит ~3 мс, так что `--set train.num_workers=0` почти не
  медленнее.
- В ансамбль сервиса идут `fold{N}.pt` (лучшая эпоха) всех фолдов, найденных
  в `runs/keypoints`; `_last.pt` — только для продолжения обучения.
- На выходе: `metrics_per_point.csv` (медиана/p90 ошибки в мм, PCK, F1
  видимости по каждой точке), `metrics_end_to_end.csv` (ошибка угла оси и
  отступов ROI против геометрии по разметке эксперта), `thresholds.csv`
  (пороги видимости, откалиброванные на OOF).

Сравнить модель с контурной геометрией на тех же 252 кадрах:

```bash
python -m service.evaluate --keypoints --out runs/metrics_keypoints.json
```

Разбор этого сравнения и условия, при которых модель стоит включить по
умолчанию, — в README, «Модель ключевых точек». Коротко: размечено всё
пригодное (242 кадра), обучены все пять фолдов, и out-of-fold модель пока
проигрывает контуру; мешают ошибки нумерации позвонков и спор об определении
низа ROI, а не объём разметки.
