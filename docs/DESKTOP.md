# Настольное приложение для Windows

Для кого: врач или лаборант, которому нужен сервис на своём компьютере без
Docker, и тот, кто собирает установщик.

Приложение — тот же сервис, что в контейнере, упакованный в один установщик.
Внутри тот же конвейер, те же веса и те же версии пакетов (`requirements.lock`),
поэтому отчёт совпадает с контейнером **побитово**: это проверено на всех 252
снимках обучающего набора — вердикты, флаги и вероятности одинаковые.

## Установка

1. Скачайте [DXA-QC-Setup-1.0.0.exe](https://github.com/theorcos239/LCT_2026/raw/master/release/DXA-QC-Setup-1.0.0.exe) (288 МБ; контрольная сумма —
   в [release/README.md](../release/README.md)) и запустите. Права администратора не нужны:
   приложение ставится в `%LOCALAPPDATA%\Programs\DXA-QC`. Для всех
   пользователей компьютера — выберите это в первом окне мастера.
2. Установщик не подписан сертификатом, поэтому Windows может показать
   SmartScreen «Система Windows защитила ваш компьютер». Нажмите
   «Подробнее» → «Выполнить в любом случае».
3. Отметьте по желанию: ярлык на рабочем столе, `dxa-qc-cli` в PATH (чтобы
   пакетная обработка работала из любой консоли).

Требования: Windows 10 или 11, 64 бита, 4 ГБ памяти, около 1 ГБ на диске.
Интернет и видеокарта не нужны. Окно использует WebView2 Runtime — он есть в
Windows 11 и в обновлённой Windows 10; если его нет, установщик предупредит,
а интерфейс откроется в браузере.

Нужна другая версия — соберите установщик сами (раздел «Сборка» ниже); там
же собирается переносной zip: распакуйте и запустите `DXA-QC.exe`, установка
не нужна.

## Что появляется в меню «Пуск»

Папка «Контроль качества DXA»:

| ярлык | что делает |
|---|---|
| **Контроль качества DXA** | окно приложения: сервис поднимается внутри на `127.0.0.1`, наружу не виден |
| Командная строка (пакетная обработка) | консоль в папке программы с подсказкой по командам |
| Веб-сервер для локальной сети | тот же интерфейс в браузере для коллег в вашей сети, порт 8000 |
| Telegram-бот | бот на этом компьютере, при первом запуске спросит токен — см. [TELEGRAM_BOT.md](TELEGRAM_BOT.md) |
| ПРОЧТИТЕ | краткая справка |

## Работа в окне

Окно — это веб-интерфейс сервиса ([USER_GUIDE.md](USER_GUIDE.md), раздел
«Веб-интерфейс»): перетащите папку с исследованиями, zip или DICOM-файлы,
листайте снимки с разметкой и нормами, отмечайте согласие с вердиктом,
скачивайте таблицу отчёта, измерения, визуализацию и DICOM SR. Файлы
сохраняются в папку «Загрузки».

Первый запуск после установки занимает до минуты: Windows проверяет новые
файлы антивирусом. Дальше окно открывается за несколько секунд.

Если запустить приложение второй раз, новый сервис не поднимается — окно
подключается к уже работающему. Закрыли окно — сервис остановлен.

## Пакетная обработка из консоли

```bat
dxa-qc-cli batch D:\исследования --out D:\результат\report.xlsx
dxa-qc-cli batch архив.zip --out report.csv --overlays overlays.zip --sr sr.zip --details details.json
dxa-qc-cli serve                     :: веб-интерфейс и API для локальной сети, порт 8000
dxa-qc-cli serve --host 127.0.0.1    :: только для этого компьютера
dxa-qc-cli bot                       :: Telegram-бот
dxa-qc-cli version
```

Ключи `batch` — те же, что у `python -m service.cli` (README, «Входные и
выходные данные»): `--roi-rule margins` — отступы ROI строго по рисунку 6 ТЗ,
`--no-cnn` — без нейросети.

## Где что лежит

| что | где |
|---|---|
| программа | `%LOCALAPPDATA%\Programs\DXA-QC` |
| журнал окна | `%LOCALAPPDATA%\DXA-QC\logs\desktop.log` |
| временные файлы заданий | `%TEMP%\dxa_qc_jobs` (удаляются через 24 ч) |
| токен Telegram-бота | `%APPDATA%\DXA-QC\bot.env` |

Удаление — «Параметры» → «Приложения» или ярлык «Деинсталлировать». Удаляются
программа, журналы, кэш окна и сохранённый токен бота.

## Как устроено

```
DXA-QC.exe (окно)                        dxa-qc-cli.exe (консоль)
   │  pywebview → WebView2                  batch → service.cli
   │                                        serve → uvicorn service.api
   └─ uvicorn service.api  127.0.0.1:8765   bot   → bot.app
            │
      конвейер service.pipeline — общий с контейнером, CLI и ботом
```

Оба exe лежат в одной папке и делят `_internal\` — Python 3.11, пакеты и
веса моделей (около 520 МБ). Вычисления в один поток, как в контейнере:
это условие побитовой воспроизводимости. Если WebView2 не запускается,
приложение открывает интерфейс в Edge, Chrome или Яндекс.Браузере в режиме
приложения (окно без адресной строки), а маленькое окно управления держит
сервис и завершает его.

Из исходников на любой ОС (Linux, macOS — окно или браузер):

```bash
pip install -r requirements.lock pywebview
python -m desktop                 # окно
python -m desktop serve           # веб-сервер для локальной сети
```

## Сборка установщика

Нужны [uv](https://docs.astral.sh/uv/) и [Inno Setup 6](https://jrsoftware.org/isdl.php)
(можно без прав администратора: `innosetup-6.x.exe /CURRENTUSER`).

```powershell
powershell -ExecutionPolicy Bypass -File desktop\build_windows.ps1
```

Скрипт создаёт окружение Python 3.11 из `requirements.lock` и
`desktop\requirements-desktop.txt`, собирает PyInstaller по
`desktop\dxa_qc.spec`, проверяет сборку (версия, загрузка моделей, отчёт на
`demo.zip`, если он есть) и пишет в `dist\`:

- `DXA-QC-Setup-1.0.0.exe` — установщик (около 290 МБ);
- `DXA-QC-1.0.0-portable.zip` — та же программа без установки;
- `DXA-QC\` — распакованная сборка.

Сборка с нуля — около 5 минут, из них половина — сжатие установщика.
Иконка рисуется скриптом `desktop\make_icons.py`.

## Ограничения

- Только Windows x64. На Linux и macOS — контейнер или `python -m desktop`.
- Установщик не подписан: SmartScreen предупреждает при первом запуске.
- Модель ключевых точек (флаг `--keypoints`) в установщик не входит: ей нужен
  torch, это ещё 2 ГБ. Она и в контейнере по умолчанию выключена.
