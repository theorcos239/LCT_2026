# Детерминированные кропы и согласование точек позвоночника

Проверено 19 октября 2026 года на 359 подтверждённых врачом фрагментах из
92 снимков позвоночника. В `configs/spine_multicrop.yaml` сохранены для каждого
типа: выбранные врачом точки, точки внутри рамки без метки, точки за рамкой,
частоты и покрытие новых окон. Последние две категории различаются: точка
внутри рамки без метки **не доказывает**, что анатомии там нет.
В `configs/spine_crop_presence.json` те же четыре состояния сохранены
отдельно для всех 359 конкретных врачебных кропов (3304 выбранных точек,
3886 вне рамки, 3 внутри без выбора, 346 без исходной метки). Это дополнение
к исходному `Processing/dxa-crops.json`, без изменения врачебной разметки.

## Четыре типа и новая нарезка

Доли указаны от высоты исходного кадра; по X берётся вся ширина. Окна выбраны
по границам всех размеченных центров L1–L4 с 10-пиксельным отступом от
искусственного края. В отличие от предыдущих вариантов, выбор рамки не
зависит от пика модели, а у каждого типа ровно одно окно.
У врача медианные границы по X тоже совпадают с краями кадра; редкие ручные
обрезы убирают до 17% ширины слева. Полная ширина сохраняет костные ориентиры
и не создаёт дополнительной искусственной границы.

| Тип | Подтверждённых кропов | Окно Y | Центры, допускаемые в сборку | Выбранные врачом центры |
|---|---:|---:|---|---|
| Th12–L1 | 89 | 0–0.44 | L1 | L1: 89; L2: 49 |
| L1–L2 | 89 | 0–0.59 | L1, L2 | L1: 86; L2: 89 |
| L2–L3 | 89 | 0.19–0.79 | L2, L3 | L2: 87; L3: 89 |
| L3–L4 | 92 | 0.37–1 | L3, L4 | L3: 92; L4: 90 |

L2 в верхнем врачебном кропе бывает и присутствующим, и отсутствующим;
постоянной маской это не выразить. Для автоматического кропа используется
только гарантированный L1. Аналогично редкие соседние уровни не попадают в
маску типа. Поле `guaranteed_points` хранит аналогичный аудит прочих точек;
в нынешнем консенсусе они не объединяются.

Проверка **без CNN** по всем размеченным исходным кадрам дала покрытие
целевых центров: 92/92 для Th12–L1, 184/184 для L1–L2, 184/184 для L2–L3,
183/183 для L3–L4. Это покрытие лишь имеющейся выборки; для нового снимка
неизвестной укладки гарантия статистическая, а не математическая.

## Сборка координат

`Predictor.predict_consensus` считает полный кадр обычным декодером цепочки,
четыре фрагмента — независимым декодером каналов. У каждого фрагмента для
каждого ожидаемого центра берётся пик даже при малой уверенности модели;
остальные центры отбрасываются по маске типа. Поэтому до геометрии у L1–L3
по три кандидата, у L4 — два. Края, диски и другие точки остаются из полного
кадра: их объединение на OOF ухудшало качество. Координаты фрагмента
переводятся обратно как
`(x + x0, y + y0)`; масштаб 0.6 мм/пиксель взят из конфига модели.

Для каждого центра первые два наблюдения не считаются автоматически верными:
кандидаты на расстоянии не более 10 мм сливаются, пара удаляется, а среднее
взвешивается числом исходных наблюдений. Операция повторяется до отсутствия
близких пар. Например, 20, 30, 32 пикселя при радиусе 10 пикселей дадут
27.33 пикселя, если пары обрабатываются в этом порядке.

Одиночный кластер считается подтверждённым. Из оставшихся кандидатов удаляются
те, что лежат слишком близко к **подтверждённому анатомическому соседу**
L1–L2–L3–L4. Порог свой для каждой пары: треть среднего расстояния между
центрами во врачебной разметке (92 снимка) — L1–L2 10.39 мм (среднее
31.18), L2–L3 10.82 мм (32.46), L3–L4 11.28 мм (33.85). Также удаляется
кандидат, лежащий не с той стороны от подтверждённого соседа по вертикали:
выше верхнего соседа или ниже нижнего (во врачебной разметке нижний центр
всегда ниже верхнего не менее чем на 22 мм). Кандидаты удаляются по одному;
после каждого удаления позвонок с единственным оставшимся кандидатом сразу
подтверждается и становится опорой для своих соседей. Если у L2
или L3 не осталось кандидатов и оба соседа подтверждены, ставится середина
между соседями с пометкой `interpolated`. Два подряд отсутствующих центра не
восстанавливаются. Неразрешённая точка имеет `visible=false`, нулевую
уверенность и `status=missing`; последующая геометрия переходит к контуру.
Все исходные и сгруппированные глобальные координаты доступны в
`multicrop.per_point` для разбора ошибок.

## Честная оценка на доступных фолдах

Прогон на одном и том же OOF наборе из 73 снимков позвоночника, фолды 0–3,
одинаковые веса и пороги. Фолд 4 отсутствует. Выбор лучшей эпохи на собственном
отложенном фолде делает эту оценку исследовательской. Кроме того, границы
окон и маски построены по всем 92 размеченным снимкам, включая отложенные
фолды. Это утечка при оценке переносимости схемы нарезки; для строгой оценки
её надо получать только по обучающим снимкам каждого фолда либо на отдельной
внешней выборке.

| Вариант | Ошибки уровня / 72 | p90 всех точек позвоночника, мм | p90 угла оси, ° | Доля принятых |
|---|---:|---:|---:|---:|
| Полный кадр | 11 | 10.72 | 1.25 | 100% |
| Прежний `auto` | 11 (2 среди принятых) | 10.60 | 1.18 | 64.4% |
| Новые фиксированные кропы + консенсус | **10** (6 среди принятых) | **10.72** | **1.16** | 89.0% |
| Медианные окна по цепочке полного кадра + консенсус | **11** (6 среди принятых) | **10.83** | **1.19** | 89.0% |

Строка фиксированных кропов пересчитана после перехода на попарные пороги
и проверку стороны. С прежним порогом 7 мм там было: 11 ошибок уровня
(6 среди принятых), p90 10.83 мм, p90 угла 1.17°, доля принятых 87.7%,
p90 центров 24.17 мм. Теперь p90 центров 21.94 мм, на принятых кадрах
консенсус исправил одну ошибку уровня и не внёс новых. Гейт по-прежнему не
пройден только из-за отсутствия пятого фолда. Строка медианных окон
посчитана ещё со старыми правилами.

Второй вариант (`--multicrop consensus_adaptive`) ближе по высоте к врачебным
окнам, но зависит от модели полного кадра. На OOF он
вместил с отступом 73/73, 141/146, 141/146 и 143/145 целевых центра по
четырём типам. Фиксированный вариант покрывает все размеченные центры и
лучше выполняет требование об обязательном присутствии целевых позвонков.

На принятом подмножестве у полного кадра тоже было **6** ошибок уровня:
консенсус не исправил и не добавил ни одной ошибки нумерации на этих кадрах.
Пять оставшихся ошибок он отметил отказом от решения вместе с четырьмя
правильными кадрами. p90 центров снизился с 24.94 до 24.17 мм; p90 всех
точек вырос на 0.11 мм. На девяти OOF кадрах с комментарием о сколиозе
p90 ошибки угла слегка выросла (1.44° → 1.50°), на остальных снизилась
(1.24° → 1.17°). Это не основание отдельно менять критерий для сколиоза.

Оба варианта проходят покрытие 80%, не ухудшают число сырых ошибок уровня и
улучшают p90 угла. Остальные условия, включая p90 всех точек и пятый
фолд, не выполнены. Отчёты `runs/keypoints_crops/metrics_crop_consensus.json`
и `runs/keypoints_crops/metrics_crop_consensus_adaptive.json`
содержат контроль хешей весов, исходного набора и конфигурации. Новая сборка
доступна через `Predictor.predict_consensus` и `evaluate --multicrop consensus`,
а сервис сможет выбрать её только после прохождения гейта на тех же весах и
конфигурации. Сейчас гейт не пройден, рабочий вердикт остаётся контурным.
Больше всего ошибок центров в L1/L4; частичный
кадр может уверенно дать пик соседнего уровня даже после правильной маски.

В части наклона сколиоз не должен считаться дефектом укладки сам по себе.
Контурный критерий уже сверяет наклон оси с независимыми краями: на имеющейся
разметке шесть кадров с углом выше порога и расхождением оценок более 2°
помечены врачом без нарушения оси (пять из них с комментарием «сколиоз»).
Точечная свёртка учитывает кривизну и неопределённость, но её G2 пока не
пройден; поэтому при отсутствии/конфликте центров контур остаётся источником
вердикта. Для будущего включения точечной оси добавлена защита: если контур
пометил угол как `axis:curved_suppressed`, а точечная свёртка считает кадр
непригодным, результат становится `undetermined` и уходит на проверку.
Отдельный порог сколиоза на 14 отмеченных случаях добавлять нельзя без риска
подогнать решение к этой выборке.

## Воспроизведение

```bash
Processing/.venv-keypoints/bin/python tools/analyze_spine_crops.py \
  --crops Processing/dxa-crops.json --pack data/keypoints.npz \
  --out configs/spine_multicrop.yaml
PYTHONPATH=src Processing/.venv-keypoints/bin/python -m dxa_qc.evaluate \
  --run runs/keypoints_crops --pack data/keypoints.npz --device mps \
  --folds 0 1 2 3 --multicrop consensus \
  --thresholds-from Processing/validation_rerun_2026-10-19/full_frame \
  --out Processing/validation_consensus_strict
Processing/.venv-keypoints/bin/python tools/report_crop_consensus.py \
  --baseline Processing/validation_rerun_2026-10-19/full_frame \
  --consensus Processing/validation_consensus_strict \
  --out runs/keypoints_crops/metrics_crop_consensus.json
# Для альтернативы: заменить режим на consensus_adaptive,
# папку на Processing/validation_consensus_adaptive и имя отчёта соответственно.
```
