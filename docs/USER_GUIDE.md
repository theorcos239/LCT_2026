# Руководство пользователя

Для кого: оператор или врач, который загружает исследования DXA и разбирает
результат. Как поднять сервис — в [DEPLOYMENT.md](DEPLOYMENT.md), как
переобучить — в [TRAINING.md](TRAINING.md). Пошаговые инструкции в PDF:
[приложение](Инструкция_приложение.pdf),
[Telegram-бот](Инструкция_Telegram-бот.pdf).

## Что делает сервис

Принимает исследования денситометрии поясничного отдела позвоночника и
проксимального (верхнего) отдела бедра в формате DICOM (стандартный формат
медицинских снимков) и для каждого снимка отвечает на три вопроса:

1. **Какая это область** — позвоночник, левое бедро, правое бедро или «не
   определена».
2. **Качественный ли снимок** — `quality_class`: 0 — да, 1 — есть нарушение.
3. **Какие именно нарушения** — список кодов, их может быть несколько.

Сервис не ставит диагноз и не оценивает плотность кости — только качество
выполнения исследования: укладку, ось, посторонние предметы, ротацию бедра и
отступы области интереса.

## Что подавать на вход

- папку с исследованиями (внутри — папки исследований, в них DICOM на любой
  глубине);
- одно исследование (папку);
- один файл `.dcm`;
- zip-архив с любым из перечисленного.

Структура подпапок значения не имеет. Повторные выгрузки одного снимка
(Lunar сохраняет их по нескольку раз с разными UID) распознаются по пикселям
и дают одну строку отчёта, а не несколько. Выгрузку из PACS (архива снимков
клиники) можно подавать как есть:
`DICOMDIR`, DICOM-отчёты без изображения (SR, PDF) и служебные файлы ОС
(`.DS_Store`, `__MACOSX/`) пропускаются и строк не дают.

## Как запустить

Основных интерфейсов три, четвёртый — Telegram-бот — необязательный бонус; анализ у всех один и тот же:

| интерфейс | когда удобен |
|---|---|
| **веб-интерфейс** | основной для оператора: сервис поднят в контейнере (`./run.sh`) или на соседнем компьютере |
| **настольное приложение** | Windows без Docker: установщик, окно с тем же интерфейсом; работает полностью локально, снимки не покидают компьютер; обновления — новым установщиком поверх старого — [DESKTOP.md](DESKTOP.md) |
| **командная строка** | пакет исследований целиком: `./run.sh batch` или `dxa-qc-cli batch` |
| **Telegram-бот** (бонус) | приятный бонус, а не обязательная часть проекта: демонстрация альтернативного интерфейса — тот же анализ отвечает в чате, с телефона; заготовка для доработки и интеграции в другие сервисы (корпоративный мессенджер, МИС); файлы проходят через серверы Telegram, поэтому только обезличенные данные; по умолчанию не запускается — [TELEGRAM_BOT.md](TELEGRAM_BOT.md) |

**Через веб-интерфейс** — основной способ для оператора. Сервис поднят
(`./run.sh`, см. DEPLOYMENT.md) — откройте в браузере `http://localhost:8000/`.
В настольном приложении тот же интерфейс открывается в собственном окне.

Интерфейс устанавливается как приложение: в Chrome или Edge — значок
«Установить» в адресной строке (или меню → «Установить приложение»). Он
появится в меню «Пуск» и откроется в отдельном окне без адресной строки. Если
сервис остановлен, вместо ошибки браузера откроется страница с подсказкой, как
его запустить.

1. Перетащите в окно папку с исследованиями, zip или несколько DICOM-файлов
   (или кнопки «Выбрать папку» / «Выбрать файлы»). Выгрузку из PACS можно
   подавать как есть; папка упаковывается прямо в браузере.
2. Идёт прогресс по исследованиям. Затем — сводка (сколько кадров качественных,
   с нарушением, на ручной разбор, со сбоем) и таблица, сгруппированная по
   исследованиям. Первым выбирается кадр с замечанием.
3. Справа — снимок с разметкой, вердикт и каждый критерий: что измерено, с
   какой нормой сравнивалось и насколько близко к границе (полоска с зелёной
   зоной нормы), ниже — пояснения к флагам. Щелчок по снимку — на весь экран
   с увеличением.
4. Отметьте, согласны ли вы с вердиктом, при желании с комментарием, и
   переходите к следующему кадру. Отметки хранятся в этом браузере отдельно
   для каждого задания и выгружаются кнопкой «Мои отметки .csv».

Плитки сводки и метки типов нарушений — это фильтры: щелчок показывает только
эти кадры, повторный — снимает фильтр. Есть поиск по файлу, исследованию и
UID, фильтр по области и сортировка «сначала нарушения». Кнопки «Скачать» —
таблица ТЗ, измерения в JSON, DICOM SR (структурированное текстовое
заключение, которое PACS показывает рядом со снимком) и визуализация; в
отличие от пакетного режима визуализация здесь — для всех снимков, не только с
нарушениями. Ссылка в адресной строке ведёт на задание — её можно открыть после
перезагрузки или отправить коллеге, пока результаты хранятся на сервере.

| клавиша | действие |
|---|---|
| `J` / `↓`, `K` / `↑` | следующий / предыдущий кадр |
| `N` | следующий кадр с нарушением |
| `A` / `D` | согласен / не согласен с вердиктом |
| `C` | комментарий |
| `F` / `Enter` | снимок на весь экран (колесо — масштаб, перетаскивание — сдвиг) |
| `/` | поиск (`Enter` или `Esc` — назад к списку) |
| `?` | справка |

Клавиши работают и в русской раскладке: J = О, K = Л, N = Т, A = Ф, D = В,
C = С, F = А.

**Пакетно, из командной строки** (отчёт и все дополнительные файлы в `./out`):

```bash
./run.sh batch /путь/к/исследованиям
```

В установленном настольном приложении — то же без Docker:

```bat
dxa-qc-cli batch D:\исследования --out report.xlsx --overlays overlays.zip --sr sr.zip
```

**Через Telegram-бота**: пришлите боту DICOM-файлы или zip как файл — в ответ
придут вердикт по каждому снимку, снимки с разметкой и таблица отчёта
([TELEGRAM_BOT.md](TELEGRAM_BOT.md)). Бот — приятный бонус, а не обязательная
часть проекта: демонстрация альтернативного интерфейса, тот же анализ отвечает в чате, с телефона. Это заготовка для
дальнейшей доработки и интеграции в другие сервисы — корпоративный мессенджер
медорганизации, МИС, систему уведомлений. Для реальных данных пациентов он не
предназначен: файлы проходят через серверы Telegram (ТЗ 3.2), поэтому только
обезличенные снимки; в основной контур бот не входит и по умолчанию не
запускается.

**Через веб-API** (сервис уже поднят, см. DEPLOYMENT.md):

```bash
# один снимок — ответ сразу
curl -F file=@снимок.dcm http://localhost:8000/analyze

# пачка — задание в фоне
curl -F file=@исследования.zip 'http://localhost:8000/batch?fmt=xlsx&overlays=true&sr=true'
curl http://localhost:8000/jobs/<id>                 # статус и прогресс «12/252»
curl -OJ http://localhost:8000/jobs/<id>/report      # таблица, когда state = done
```

Интерактивная страница со всеми эндпоинтами и кнопкой «Try it out» —
`http://localhost:8000/docs`; она работает без интернета, Swagger UI отдаётся
из локальной копии.

## Что получается на выходе

| файл | что внутри |
|---|---|
| `report.xlsx` / `report.csv` | итоговая таблица, строка на снимок (ТЗ 2.5) |
| `details.json` | все измерения: углы, миллиметры, вероятности, флаги — для разбора спорных случаев |
| `overlays.zip` | PNG с разметкой вердикта: найденные ориентиры, пороги ТЗ, тепловая карта нейросети. В пакетном режиме — только для снимков **с нарушениями**, в веб-интерфейсе и боте — для всех снимков |
| `sr.zip` | DICOM SR с текстовым заключением для **каждого** снимка |

### Колонки таблицы

Первые восемь — ровно как в ТЗ:

| колонка | значение |
|---|---|
| `path_to_study` | путь к исследованию |
| `study_uid`, `image_uid` | UID исследования и снимка из DICOM |
| `anatomical_region` | `spine`, `lh`, `rh` или `unknown` |
| `quality_class` | 0 — качественное, 1 — есть нарушение |
| `violation_type` | коды нарушений через `;` |
| `processing_status` | `Success` или `Failure` |
| `time_of_processing` | секунды на снимок |

Правее — пояснения: `projection` (`AP` — передне-задняя проекция, стандартная
для DXA позвоночника и бедра); `violation_description` (по-русски);
`quality_probability` — вероятность того, что на снимке есть нарушение (от 0
до 1; по ней удобно сортировать очередь на проверку: сверху — самые
сомнительные снимки); `p_spine_position`, `p_spine_axis`,
`p_spine_artifacts`, `p_hip_rotation`, `p_hip_roi` — вероятности по каждому
критерию; `flags`, `region_confidence`, `file_name`, `duplicates` (сколько
копий схлопнуто), `error` (текст ошибки для `Failure`).

### Коды нарушений

| код | что означает | как проверить глазами |
|---|---|---|
| `spine_position` | некорректная укладка: не видны верхние края подвздошных костей | внизу кадра по бокам от позвоночника нет гребней |
| `spine_axis` | ось позвоночника отклонена больше чем на 5° | угол в `details.json` → `details.spine.axis.angle_deg` |
| `spine_artifacts` | посторонние предметы или наложения | тонкая яркая дуга или пятно вне позвоночника; на оверлее оранжевым — где их видит нейросеть |
| `hip_rotation` | некорректная ротация (поворот) бедра | малый вертел (костный выступ на внутренней стороне бедра ниже шейки) почти не виден или выступает слишком сильно; на оверлее оранжевым — где нейросеть видит признак ротации |
| `hip_roi` | поле сканирования бедра короче нужных 12.9 см — отступы области интереса не помещаются (правило по умолчанию, как оценивает эксперт; подробности под таблицей) | `details.hip_roi`: `scan_length_mm` — длина поля, `min_length_mm` — нужная длина |
| `undetermined` | область не определена: снимок не похож на DXA позвоночника или бедра | снимок уходит на ручной разбор |

Нужные 12.9 см для `hip_roi` складываются из 3 см над верхушкой большого
вертела (костного выступа на наружной стороне бедра), 6.9 см от него до
седалищной кости и 3 см под ней. Режим `--roi-rule margins` (у API —
переменная `DXA_QC_ROI_RULE`) выносит вердикт дословно по рисунку 6 ТЗ: 3 см
сверху от верхушки большого вертела, 3 см снизу от нижней точки седалищной
кости, 2 см сбоку от наружного контура бедра. Эти отступы измеряются при любом
правиле и лежат в `details.hip_roi`: `m_top_mm`, `m_bottom_mm`, `m_lat_mm` и
`margins_ok`; поле `roi_rule` говорит, каким правилом вынесен вердикт.

### Как читать флаги

Флаги в колонке `flags` — не нарушения, а пометки «здесь измерение менее
надёжно, посмотрите сами». Префикс говорит, к какому измерению флаг относится:

| флаг | что он значит |
|---|---|
| `*:estimates_disagree` | два независимых способа измерения дали разный ответ: вердикт вынесен по основному, но уверенность низкая — посмотрите снимок сами |
| `rotation:cnn_vs_geometry_disagree`, `artifacts:cnn_vs_geometry_disagree` | нейросеть и измерение не согласны; вердикт вынесен по их объединённой оценке (см. ниже), снимок стоит открыть |
| `cnn:unavailable(...)` | нейросеть не загрузилась — ротация и посторонние предметы оценены только измерением |
| `orientation:mirrored_lr` и др. | снимок выгружен зеркально или перевёрнутым и приведён к стандартному виду по тегу `PatientOrientation` |
| `axis:curved` | позвоночник изогнут (сколиоз): формально ось вертикальна. Эксперт при сколиозе нарушение оси обычно не ставит — если стоит `spine_axis`, посмотрите снимок сами |
| `position:iliac_missing_one_side` | гребень не найден только с одной стороны |
| `I:strict_mask`, `I:anatomical_prior` | нижняя точка седалищной кости (низ ROI бедра) найдена по строгой маске или не найдена и взята по анатомии («вертел + 69 мм») — нижний отступ проверьте по картинке; на вердикт по длине поля не влияет |
| `rotation:no_contour`, `rotation:no_anchor` | ротацию измерить не удалось |
| `region:не похож на DXA` / `кадр перевёрнут` / `низкий контраст` | почему снимок не принят фильтром области |
| `keypoints:*` | только при включённой модели ключевых точек |

**Ротация бедра и посторонние предметы** оцениваются двумя способами —
измерением и нейросетью, а вердикт выносит объединённая оценка нейросети и
измерения (дальше — просто объединённая оценка). В карточке снимка видны обе
составляющие: вероятность по объединённой оценке с порогом и само измерение
(выступ малого вертела в мм² с коридором нормы). Ротация остаётся самым
трудным критерием (подробности в README): если нейросеть и измерение
расходятся, снимок помечен флагом — откройте его и посмотрите на тепловую
карту.

## Если что-то пошло не так

| что видно в отчёте | что это значит | что делать |
|---|---|---|
| `processing_status = Failure`, текст в `error` | файл не читается как DICOM или битый | проверить файл; остальные снимки пачки обработаны |
| `anatomical_region = unknown`, `undetermined` | снимок не похож на DXA позвоночника/бедра (или перевёрнут) | разобрать вручную |
| `quality_class = 1` при `Failure` | непрочитанный снимок намеренно не считается качественным | — |
| строк меньше, чем файлов | повторные выгрузки схлопнуты, см. `duplicates` | — |

Сервис ничего не отправляет в интернет и не изменяет исходные файлы: папка с
исследованиями подключается только на чтение.
