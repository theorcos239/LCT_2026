1. Назначение, возможности и ограничения

Если пациент на денситометре уложен неправильно, поле сканирования слишком короткое или в кадр попал посторонний предмет, измерение плотности кости недостоверно, и пациента вызывают повторно. Сервис проверяет снимки DXA поясничного отдела позвоночника и проксимального отдела бедра до того, как исследование уйдёт к врачу. Он сам определяет область снимка, проверяет пять критериев ТЗ и объясняет каждое замечание числом: «ось позвоночника отклонена на 6.6° при норме до 5°». Диагноз сервис не ставит и плотность кости не оценивает.

Возможности

  • Определяет область: позвоночник, левое или правое бедро. Снимок, не похожий на DXA, получает область unknown и уходит на ручной разбор.
  • Ставит класс качества (0 — качественный, 1 — есть нарушение) и перечисляет все сработавшие нарушения.
  • Обрабатывает папку, zip-архив или выгрузку из PACS; повторы одного снимка сводит в одну строку.
  • Выдаёт таблицу в формате ТЗ (xlsx или csv), файл всех измерений, снимки с разметкой и заключение DICOM SR по каждому снимку.
  • Работает через контейнер (командная строка и HTTP API), веб-интерфейс и настольное приложение для Windows и macOS.
  • Работает локально: без интернета и без видеокарты. Исследование обрабатывается за 1.6 с (медиана), повторный запуск даёт тот же результат бит в бит.
КритерийЧто проверяетсяКод

Ограничения

  • Один аппарат. Все обучающие снимки сделаны на GE Lunar Prodigy Advance. Масштаб задан константой (0.6 мм/пиксель), потому что поле PixelSpacing в файлах пусто. На другом аппарате масштаб перепроверяют, а модели дообучают (раздел 11).
  • Разметка оператора не проверяется: в данных её нет ни на изображении, ни в служебных полях.
  • Ось и сколиоз. При сколиозе эксперт нарушение оси не ставит. Сервис в таких случаях вердикт по оси не выносит и ставит пометку (раздел 9).
  • Верх укладки (Th12) проверяется только с моделью ключевых точек. В контейнере и настольном приложении она выключена.
  • Мало примеров: от 6 до 36 нарушений на критерий, поэтому доверительные интервалы метрик широкие.
  • Поддержка решения, а не медицинское изделие. Окончательное решение о качестве принимает специалист.

4. Сборка и запуск контейнера

git clone https://github.com/theorcos239/LCT_2026 && cd LCT_2026
./build.sh                              # образ dxa-qc:1.0.0, 1–3 минуты
./run.sh batch /путь/к/исследованиям    # результат — в ./out
./run.sh                                # веб-интерфейс и API: http://localhost:8000

После ./run.sh batch в папке out появятся report.xlsx, details.json, overlays.zip и sr.zip (раздел 6). Папка с исследованиями подключается только на чтение. build.sh сначала проверяет, что на месте все файлы моделей, и без них образ не собирает: иначе сервис молча потерял бы часть критериев.

Параметры командной строки: --details, --overlays, --sr — дополнительные файлы; --roi-rule — правило отступов; --no-cnn — без нейросети; --json, --quiet — сводка в JSON, без вывода хода работы.

Проверка: curl -s localhost:8000/health → у region_clf, spine_appearance, cnn_rotation, cnn_artifacts должно быть true (keypoints: false — норма для рабочего образа).

Воспроизводимость. Все вычисления идут в один поток (OMP_NUM_THREADS=1 задан в образе): при многопоточности порядок сложения меняется, и последние знаки результата «плавают». Для скорости большой набор делят на части и запускают несколько процессов.

6. Формат входных и выходных данных

Вход

Исследования DICOM в том виде, в каком их выгружает денситометр: папка исследований (файлы на любой глубине), одно исследование, один файл .dcm или zip с любым из этого. DICOMDIR, отчёты без изображения и служебные файлы ОС пропускаются. Читаются несжатые и сжатые файлы (RLE, JPEG Baseline, JPEG Lossless, JPEG-LS, JPEG 2000). MONOCHROME1 переворачивается, VOI LUT применяется, ориентация приводится по PatientOrientation, зеркальная выгрузка отражается. Повторы находятся по пикселям: в обучающем наборе 499 файлов дают 252 уникальных снимка. Персональные данные не используются.

7. Модель, предобработка и постобработка

  1. Чтение: поиск исследований, чтение DICOM, удаление повторов.
  2. Область: позвоночник, левое или правое бедро; снимки, не похожие на DXA, — на ручной разбор.
  3. Критерии: измерения в миллиметрах и градусах по контуру кости.
  4. Второе мнение: для ротации и посторонних предметов к измерению добавляется нейросеть.
  5. Вердикт и отчёт: сравнение с порогами, вероятности, таблица, разметка, DICOM SR.

Основа решения — измерения, а не нейросеть «от снимка к вердикту»: нарушений от 6 до 36 на критерий, и большую сеть на этом не обучить. Кроме того, измерение («ось 6.6°») специалист проверяет глазами за секунду.

Предобработка

Яркость и ориентация приводятся к стандарту (раздел 6). Масштаб — 0.600 мм/пиксель для позвоночника и 0.607 мм для бедра. Для нейросети яркость нормализуется по перцентилям 0.5–99.5 (снимки на 12 и 16 бит её не ломают), правое бедро отражается в левое, длинная сторона приводится к 320 пикселям.

Постобработка

  • Объединённая оценка для ротации и предметов: p = σ(a·logit(p_нейросети) + b·измерение + c); подбираются только три коэффициента и порог.
  • Вероятности: по каждому критерию; общая quality_probability = 1 − Π(1 − pᵢ).
  • Класс: quality_class = 1, если сработал хотя бы один критерий.
  • Пометки «проверьте глазами», если две независимые оценки расходятся (раздел 9).
  • Если нейросеть не загрузилась, критерий считается по измерению с пометкой cnn:unavailable.

Модель ключевых точек (дополнительно)

U-Net с энкодером ResNet-34 находит 29 анатомических точек; обучена на 242 размеченных снимках и 359 подтверждённых врачом фрагментах. В рабочем образе и настольном приложении выключена: нужны PyTorch и отдельные веса. Включается переменной DXA_QC_KEYPOINTS=1. Сейчас она добавляет проверку покрытия Th12 (менее 5% тела — нарушение укладки, 5–50% — пометка для проверки человеком) и справочную оценку сколиоза по L1–L4. Вердикт по оси она не заменяет: на обучающем наборе выигрыша перед контуром нет (подробно — docs/KEYPOINTS.md).

Качество на обучающем наборе

Оценка out-of-fold: 100 исследований разбиты на пять частей, каждый снимок проверен моделью, обученной на остальных четырёх; снимки одного пациента — в одной части. В скобках — 95% доверительный интервал. Числа относятся к конфигурации до 20.10.2026, когда отступы бедра оценивались по длине поля; после перехода на рисунок 6 ТЗ и исправления эталона полный сопоставимый прогон ещё не выполнен.

8. Известные ошибки и способы их обработки

Необработанные ошибки наружу не выходят (ТЗ, п. 2.7): любая ошибка становится строкой со статусом Failure и текстом в колонке error, обработка остальных снимков продолжается. Такая строка получает quality_class = 1.

9. Руководство пользователя

Для лаборанта или врача, который загружает исследования и разбирает результат. Пошаговая инструкция со снимками экрана — Инструкция_приложение.pdf.

СпособКогда удобенКак открыть
веб-интерфейссервис запущен на сервере клиникиадрес сервиса в браузере, например http://localhost:8000/
приложение Windows / macOSкомпьютер без Docker, всё локальноярлык «Контроль качества DXA»
командная строкабольшая папка без окна./run.sh batch или dxa-qc-cli batch

Установка приложения

  • Windows: запустите DXA-QC-Setup-1.0.0.exe (права администратора не нужны). Если появится «Система Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае»: установщик не подписан.
  • macOS: откройте DXA-QC-1.1.0-macos-arm64.dmg и перетащите «DXA-QC» в «Программы». При первом запуске щёлкните приложение правой кнопкой → «Открыть» → «Открыть»: приложение не заверено Apple.

Первый запуск занимает до минуты. Интернет не нужен; новая версия ставится поверх старой, отметки специалиста сохраняются.

Проверка исследований

  1. Перетащите в окно папку, zip-архив или файлы DICOM (или «Выбрать папку» / «Выбрать файлы»). Выгрузку из PACS подавайте как есть.
  2. Через пару секунд на исследование появится сводка и таблица; первым выбирается снимок с замечанием. Плитки сводки и метки нарушений работают как фильтры.
  3. Справа — снимок с разметкой, вердикт и каждый критерий: что измерено и с какой нормой сравнивалось. Щелчок по снимку открывает его на весь экран.
  4. Отметьте «согласен» или «не согласен» и при желании добавьте комментарий.

Клавиши: J/K или стрелки — следующий/предыдущий снимок, N — следующий с нарушением, A/D — согласен/не согласен, C — комментарий, F — на весь экран, / — поиск, ? — справка. Работают и в русской раскладке.

Скачать можно таблицу (.xlsx), измерения (.json), визуализацию (.zip), DICOM SR (.zip) и свои отметки (.csv). Результаты обработки хранятся 24 часа.

Как читать результат

Класс 0 — снимок качественный, 1 — есть хотя бы одно нарушение; перечислены все. Пометка в колонке flags — не нарушение, а знак «измерение здесь менее надёжно, посмотрите сами»:

ПометкаЧто значит
*:estimates_disagreeдва независимых способа измерения дали разный ответ
*:cnn_vs_geometry_disagreeнейросеть и измерение не согласны; вердикт по объединённой оценке
axis:curved_suppressedпозвоночник изогнут (сколиоз): угол отражает форму, а не укладку, вердикт по оси не ставится
scoliosis:presentсправочно: по точкам L1–L4 есть выраженная дуга (только с моделью точек)
position:th12_*верх укладки по Th12 нужно проверить глазами (только с моделью точек)
orientation:mirrored_lrснимок выгружен зеркально и приведён к стандарту
I:anatomical_priorседалищная кость не найдена, нижний отступ оценён по типичной анатомии
cnn:unavailable(...)нейросеть не загрузилась, оценка только по измерению

Пакетная обработка без окна: dxa-qc-cli batch D:\исследования --out report.xlsx --overlays снимки.zip --sr sr.zip. В приложении для macOS утилита лежит внутри пакета: /Applications/DXA-QC.app/Contents/MacOS/dxa-qc-cli.

10. Руководство по развёртыванию

Для инженера, который ставит сервис на сервер клиники или проверочный стенд.

docker save dxa-qc:1.0.0 | gzip > dxa-qc-1.0.0.tar.gz   # на машине с интернетом
docker load < dxa-qc-1.0.0.tar.gz                        # на сервере без интернета
docker run -d --name dxa-qc -p 127.0.0.1:8000:8000 --restart unless-stopped dxa-qc:1.0.0
docker ps                                               # STATUS: healthy
docker logs dxa-qc

Встроенная проверка раз в 30 секунд запрашивает /health; --restart unless-stopped поднимает сервис после сбоя и перезагрузки.

ПеременнаяПо умолчаниюСмысл
DXA_QC_ROI_RULEmarginsправило отступов бедра: margins или scan_length
DXA_QC_CNNвключено0 — без нейросети
DXA_QC_KEYPOINTSвыключено1 — модель точек (образ Dockerfile.keypoints, веса монтируются снаружи)
DXA_QC_JOB_TTL_HOURS24срок хранения результатов заданий
OMP_NUM_THREADS1условие воспроизводимости; не менять

Безопасность

  • Исходные снимки не изменяются: папка подключается только на чтение. Ни один запрос не уходит в интернет; телеметрии и проверки обновлений нет.
  • Процесс в контейнере работает не от root; zip-архивы проверяются на выход путей за пределы папки.
  • У API нет пароля. Для доступа из сети перед сервисом ставят обратный прокси с HTTPS и паролем; готовая конфигурация nginx — deploy/bigdata10.nginx.conf, пример стенда — docs/BIGDATA10.md (контейнер слушает только 127.0.0.1, наружу — nginx с HTTPS и паролем).

Эксплуатация

  • Задания хранятся в памяти процесса и временной папке; перезапуск контейнера их стирает. Очень большой набор надёжнее обрабатывать ./run.sh batch.
  • Нагрузка масштабируется несколькими контейнерами или процессами; внутри процесса один поток — намеренно.
  • Для пилота сервис ставят за DICOM-роутером: он получает копии исследований, а заключения SR возвращаются в PACS рядом со снимком.
  • Веб-сервер для локальной сети без Docker — dxa-qc-cli serve (порт 8000); только в доверенной сети.

Проверка и обновление

curl -s localhost:8000/health ; curl -s localhost:8000/version
python -m service.test_service      # формат, устойчивость, API, повторяемость
docker rm -f dxa-qc && docker rmi dxa-qc:1.0.0   # удаление

Обновление — собрать или загрузить новый образ и пересоздать контейнер с теми же переменными. Приложение для Windows удаляется через «Параметры → Приложения», для macOS — перемещением в Корзину; перед этим выгрузите отметки специалиста.

11. Обучение и дообучение моделей

Для разработчика, который переобучает модели или переносит сервис на другой аппарат. Обучающий набор в репозиторий не входит: папку НД_для_обучения/ (снимки и разметка.xlsx) кладут в корень проекта, рядом — region_clf/labels.csv (область каждого снимка) и folds.csv (разбиение на пять частей; снимки одного исследования всегда в одной части).

pip install -r requirements.txt
python -m region_clf.make_labels       # 1. эталон области
python -m region_clf.train --stress    # 2. модель области
python -m spine_qc.calibrate --sweep   # 3. пороги позвоночника
python -m hip_rotation.calibrate       # 4. нормы ротации
python -m hip_roi.evaluate && python -m hip_roi.probability   # 5. отступы ROI
pip install -r requirements-train.txt
python -m cnn_qc.train --criterion rotation    # 6. нейросети
python -m cnn_qc.train --criterion artifacts
python -m service.evaluate             # 7. метрики сервиса с интервалами

Шаги 2–5 независимы; шаг 6 строит объединённую оценку поверх измерений шагов 3–4. Калибровка измерений — около минуты на ноутбуке, нейросеть — около 6 минут на критерий на видеокарте. --calibrate-only пересчитывает только коэффициенты объединённой оценки. Каждый скрипт печатает out-of-fold метрики — ориентироваться нужно на них. Нормы отступов (3, 3, 2 см) взяты из ТЗ и не подбираются.

МодульФайлы результата
region_clfregion_clf/model.joblib
spine_qcspine_qc/thresholds.json, model.joblib
hip_rotation, hip_roihip_rotation/thresholds.json, hip_roi/probability.json
cnn_qccnn_qc/<критерий>/model_0..2.onnx, meta.json

Дообучение и перенос

  1. Добавьте исследования в НД_для_обучения и строки в разметка.xlsx; допишите их в folds.csv, не меняя части старых.
  2. Выполните шаги 1–7 и сравните метрики с прежними: разница в пределах доверительного интервала — случайность.
  3. Для другого аппарата сначала проверьте масштаб (позвонок с диском — 27–36 мм; константы в spine_qc/geometry.py, hip_roi/geometry.py) и долю снимков с undetermined.

Модель ключевых точек обучается отдельно (нужны torch и видеокарта или Apple MPS): PYTHONPATH=src python -m dxa_qc.train --config configs/keypoints_crops.yaml. Подробно — docs/TRAINING.md и docs/KEYPOINTS.md.
