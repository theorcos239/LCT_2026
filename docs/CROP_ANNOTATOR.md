# Разметка врачебных фрагментов на iPad

Инструмент создаёт **дополнительную** разметку к существующим точкам. Он не
изменяет `data/razmetka_aleksandra_2026-09-22_2241.json` и не создаёт новые
метки качества. Каждый фрагмент ссылается на исходный снимок по тому же `id`,
который использует `src/dxa_qc/pack.py`.

## Подготовка на компьютере

```bash
python3 tools/build_crop_annotator.py
python3 tools/serve_crop_annotator.py
```

Первый шаг создаёт `Processing/crop_annotator.html` со встроенными 252 снимками
и исходной разметкой точек. Если старого `Processing/razmetka_all.html` нет в
рабочем дереве, сборщик читает его из коммита `b26b8d4`. Оба HTML-файла
содержат медицинские изображения и игнорируются Git.

Для iPad и компьютера нужна одна Wi-Fi сеть. Узнайте локальный IP компьютера
в настройках сети и откройте в Safari адрес, который напечатает сервер,
заменив `IP-КОМПЬЮТЕРА` на этот IP. Сервер выдаёт только эту страницу по
случайному URL. Разметка хранится в браузере iPad и скачивается как JSON;
сервер её не принимает. Если открыть HTML непосредственно на iPad и Safari
позволит запустить локальный файл, сервер не нужен.

## Работа врача

1. Выбрать область и снимок. Можно искать по порядковому номеру или `id`.
2. Нажать «Новая рамка» и провести пальцем по нужному фрагменту. Углы и всю
   рамку можно передвинуть; кнопки `＋` и `−` меняют масштаб просмотра.
3. Коснуться нужных точек на снимке или в списке справа. Доступны только
   точки, у которых есть координата в прежней разметке и которые лежат внутри
   рамки. Так новая разметка остаётся совместимой с существующим набором.
4. Нажать «Подтвердить фрагмент». Можно добавить несколько фрагментов одного
   снимка. Черновики тоже сохраняются, но для обучения брать только
   `status: "confirmed"`.
5. Нажать «Скачать JSON». Для продолжения работы на другом iPad или после
   очистки Safari нажать «Загрузить JSON».

Полученный файл можно проверить на компьютере:

```bash
python3 tools/check_crop_json.py путь/к/dxa-crops-2026-10-17.json
```

Автосохранение в Safari помогает пережить перезагрузку страницы, но файл JSON
нужно скачивать после сеанса: хранилище браузера может очищаться.

## Формат JSON

```json
{
  "format": "dxa-crops-v1",
  "schema_version": 1,
  "source": {
    "html": "Processing/razmetka_all.html",
    "html_commit": "b26b8d4",
    "annotations": "razmetka_aleksandra_2026-09-22_2241.json"
  },
  "crops": [
    {
      "id": "crop-...",
      "image_id": "2539404986",
      "region": "hip",
      "box": {"x0": 40, "y0": 30, "x1": 210, "y1": 240},
      "included_points": ["trochanter_major"],
      "status": "confirmed",
      "image_size": {"w": 280, "h": 310},
      "points_crop": {"trochanter_major": {"x": 161.7, "y": 48.1}}
    }
  ]
}
```

`box` задан в **пикселях исходного снимка**, без масштабирования интерфейса.
Левый верхний угол включён, правый нижний исключён: для массива снимка
`fragment = image[y0:y1, x0:x1]`. `image_id` совпадает с ключом в исходном
JSON разметки. `included_points` — подтверждённые врачом точки, а
`points_crop` содержит их координаты после вычитания `x0, y0`; исходные
координаты и состояния точек остаются в прежнем наборе. Несколько кропов
одного снимка **не являются независимыми исследованиями**: все наследуют
фолд исходного снимка, чтобы не было утечки при оценке.

JSON не содержит пиксели снимков. Для восстановления фрагмента нужен
исходный HTML или DICOM, сопоставленный тем же `image_id` через
`src/dxa_qc/pack.py`.

## Добавление в обучение модели точек

Полученный от врача DOCX преобразован в `Processing/dxa-crops.json` командой
`python3 tools/docx_to_crop_json.py '/Users/trilin/Downloads/Пустой 2.docx'`.
Экспорт содержит 367 фрагментов позвоночника: 359 подтверждённых и 8
черновиков. Все 359 подтверждённых сопоставились с 92 исходными снимками
`data/keypoints.npz`; ничего не пропущено. Готовый профиль
`configs/keypoints_crops.yaml` подключает именно этот JSON к **новому**
прогону `runs/keypoints_crops` и сохраняет прежний pack для валидации.

```bash
PYTHONPATH=src python -m dxa_qc.train --config configs/keypoints_crops.yaml
```

При нехватке времени можно ограничить фолды и эпохи через `--set`; сравнение
качества имеет смысл только на тех же отложенных исследованиях и с той же
процедурой оценки. Исходный `runs/keypoints` новым профилем не перезаписывается.

Сохраните JSON локально, например в `Processing/dxa-crops.json`, и укажите
его в конфиге без изменения исходного `data/keypoints.npz`:

```bash
PYTHONPATH=src python -m dxa_qc.train --config configs/keypoints.yaml \
  --set data.crops=Processing/dxa-crops.json \
        train.out_dir=runs/keypoints_crops \
        train.init_dir=runs/keypoints \
        'train.folds=[0,1]' train.epochs=50
```

`train.init_dir` необязателен: он подхватывает ранее обученные веса тех же
фолдов и ускоряет короткий эксперимент. Для каждого фолда используются
только подтверждённые кропы из **обучающих исследований**. Кропы отложенных
исследований не участвуют в обучении этого фолда; проверка и подбор порогов
по-прежнему идут на исходных полных кадрах. У правого бедра рамка автоматически
отражается вместе с изображением, как в прежнем `keypoints.npz`.

Каждый врачебный кроп добавляется как отдельный обучающий пример; исходный
полный кадр остаётся в наборе. Выбранные врачом точки получают прежние
координаты с вычетом начала рамки. Ранее размеченные точки вне рамки получают
состояние `ABSENT`. Если точка геометрически внутри рамки, но врач её не
выбрала, она получает `UNLABELED`: это не доказывает её отсутствие, и модель
не обучается подавлять такой пик. Исходные `UNLABELED` и каналы другой
области остаются без изменений. Черновики не используются.
Если снимок не вошёл в `keypoints.npz`, его кроп пропускается с сообщением.
Для воспроизводимости рядом с весами записывается SHA-256 JSON; если врач
обновит файл, запустите обучение в новом `train.out_dir`.
