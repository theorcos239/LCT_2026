# Валидация модели точек

**Текущий прогон:** `runs/keypoints_crops`, фолды 0–3. Числа и сравнение с
геометрией — в [сводке для команды](ИТОГ_МОДЕЛЬ_ТОЧЕК_2026-10-19.md).
Примеры ниже с `runs/keypoints` относятся к более раннему прогону.

## Протокол и его ограничения

Во время обучения `foldN.pt` сохраняет EMA-веса с лучшей медианной ошибкой
одиночного прохода. При `checkpoint_every` отдельно измеряются общий p90 и
p90 позвоночника через рабочий инференс с TTA и цепочкой. Лучшие EMA-веса по
p90 позвоночника сохраняются в `tail_foldN.pt`; этот файл не подхватывается
ансамблем автоматически. Выбирать между кандидатами следует после сравнения
OOF-качества по ошибкам уровня, пропускам и сквозным метрикам, а не только по
медиане. `foldN_history.csv` содержит p90 одиночного прохода на каждой эпохе
и p90 рабочего инференса на эпохах записи чекпоинта.

- Разбиение фиксировано в `folds.csv` **по исследованиям**. В обучении фолда
  отсутствуют все снимки его отложенных исследований. Врачебные кропы наследуют
  исследование исходного кадра и добавляются только в обучение остальных фолдов.
- Координаты и уверенности для фолда получают только его `foldN.pt`. Пороги
  видимости для **оценки** этого фолда подбираются на OOF-предсказаниях остальных
  фолдов, включая их обрезанные варианты. После этого координаты пересчитываются:
  декодер уровней L1–L4 зависит от порогов.
- Один общий `thresholds.csv`, подобранный по всем фолдам, нужен для итогового
  ансамбля в сервисе. Метрики на тех же OOF-кадрах с этим общим порогом являются
  диагностикой прогона, а не независимой оценкой порога.
- В раннем прогоне с двумя фолдами перекрёстный порог каждого подбирался
  всего на одном другом фолде. Для нового прогона пороги рассчитаны по трём
  остальным фолдам; пятый фолд пока не обучен.

**Предел независимости:** лучшую эпоху `foldN.pt` обучение выбирало по ошибке
на том же отложенном фолде. Кроме того, модели остальных фолдов, чьи OOF-выходы
используются для подбора порога фолда N, обучались в том числе на исследованиях
N. Перекрёстный порог убирает прямую подгонку порога по ответам N, но не делает
весь процесс строгой вложенной валидацией. Для финальной оценки без этого
смещения нужен отдельный внешний тест или вложенный отбор эпохи и порогов
внутри обучающих исследований каждого внешнего фолда.

Команда для OOF-оценки с перекрёстным порогом **при наличии весов
соответствующего прогона**:

```bash
PYTHONPATH=src python -m dxa_qc.evaluate \
  --run runs/keypoints_crops --pack data/keypoints.npz --folds 0 1 2 3 \
  --out Processing/validation_crops4
```

`metrics_eval_summary.csv` теперь имеет поле `localization_thresholds=crossfit`:
ошибки координат, угла и уровней рассчитаны после повторного инференса с
порогом из других фолдов. Колонки `halluc_crossfit` и `miss_crossfit`
показывают доли ложной видимости и пропусков. `halluc_own` и `miss_own` —
диагностика с общим сервисным порогом. `--calibrate` переписывает сервисный
`thresholds.csv`; для простого сравнения запускать его не требуется.
В той же папке сохраняются `oof_evaluated.npz` для полных снимков и
`oof_evaluated_truncated.npz` для обрезанных: предсказания после перекрёстной
калибровки и порог каждого снимка. `level_err_frames_chain` считает ошибки
уровня по всем пикам, в том числе у центров, скрытых порогом.
`level_err_frames_found / spine_frames_all_centers_found` считает их только
там, где все L1–L4 признаны видимыми; остальные кадры оцениваются как пропуски
в метрике видимости. `e2e_found_*` считает геометрическую ошибку только на
кадрах, где все нужные точки прошли порог, и рядом указывает число таких
кадров `*_n`. Обычные `e2e_*` оценивают качество сырых координат даже при
скрытой точке. Если сравниваются несколько `--run`, имя
файла начинается с названия прогона.

Сравнивайте дообученный прогон с исходным на **одних и тех же отложенных
исследованиях**: долю снимков с правильными уровнями L1–L4, p90 ошибки
позвоночника, пропуски и ложные точки на обрезанных кадрах, ошибку угла оси и
сквозные вердикты сервиса. Медиана ошибки по всем точкам не выявляет путаницу
уровней. Долю ошибочных уровней `level_errors` оценивает приближённо: для
граничных Th12 и L5 есть допущения о геометрии.

## Посмотреть ошибки на снимках

На Mac можно дважды открыть `tools/launch_keypoint_validation.command`: он
соберёт отчёт по перекрёстной оценке нового прогона и откроет его в браузере.

```bash
PYTHONPATH=src python tools/build_keypoint_validation_report.py \
  --oof runs/keypoints_crops/oof_evaluated.npz --pack data/keypoints.npz
```

Откройте локальный `Processing/validation_report.html` в браузере. Отчёт
содержит сами DXA-снимки, поэтому лежит в игнорируемой Git папке. Есть фильтры
по фолду, области, ошибочному уровню, пропущенной и ложной точке; при выборе
снимка видны разметка, предсказание, расстояние, пик и порог для каждой точки.
Чтобы смотреть **именно перекрёстную оценку**, передайте её файл:

```bash
PYTHONPATH=src python tools/build_keypoint_validation_report.py \
  --oof Processing/validation_current/oof_evaluated.npz \
  --out Processing/validation_current/report.html
```

Для проверки пропусков и ложных точек на обрезанных кадрах подставьте
`oof_evaluated_truncated.npz` и другое имя HTML. Инструмент восстановит те же
детерминированные обрезы по `data/keypoints.npz` и покажет их с разметкой.

Старый `runs/keypoints/oof.npz` остаётся для сравнения: 98 снимков фолдов
0–1, из них 37 позвоночников и 61 бедро. Новый отчёт по умолчанию строится
из `runs/keypoints_crops/oof_evaluated.npz` (191 снимок фолдов 0–3) и
показывает результат декодера гипотез. Файл OOF не содержит тепловые карты;
для их просмотра нужны соответствующие локальные веса и
`tools/launch_keypoint_heatmaps.command`.

В репозитории и его истории Git нет ноутбуков `.ipynb`; папка `notebooks/`
игнорируется. Их проверка будет возможна после получения файлов или ссылки.
