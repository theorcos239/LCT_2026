# Просмотр настоящих тепловых карт модели точек

Локальная страница позволяет выбрать снимок отложенного фолда 0 и любую из
29 карт, наложить карту на исходный DXA-снимок, поменять прозрачность и
масштаб, а также увидеть максимум, порог видимости и локальные пики.
Страница не содержит снимков: их и карты отдаёт локальный сервер только на
`127.0.0.1`.

## Запуск на Mac

В Finder дважды нажмите
[`tools/launch_keypoint_heatmaps.command`](../tools/launch_keypoint_heatmaps.command).
На этой машине `fold0.pt` уже скачан в `Processing/drive_models/`, поэтому скрипт
запустит локальный сервер и откроет страницу. Если файл позже удалить,
откроется окно его выбора.

Для запуска из терминала нужны обученные веса
`Processing/drive_models/fold0.pt` и среда с PyTorch, NumPy и Pillow. На этой машине
изолированная среда уже подготовлена в игнорируемой папке
`Processing/.venv-keypoints`. Из корня проекта:

```bash
PYTHONPATH=src Processing/.venv-keypoints/bin/python \
  tools/serve_keypoint_heatmaps.py --device auto
```

Открыть `http://127.0.0.1:8767/`. `--device auto` выбирает Apple MPS, если
он доступен в установленном PyTorch, иначе CPU. Чтобы явно проверить MPS:

```bash
PYTHONPATH=src Processing/.venv-keypoints/bin/python \
  tools/serve_keypoint_heatmaps.py --device mps
```

При выборе нового снимка модель выполняет рабочий инференс: те же TTA и
усреднение карт, что в `dxa_qc.infer.Predictor`. В списке только снимки,
которые не использовались при обучении `fold0.pt`. При переключении каналов
карты уже выбранного снимка берутся из памяти. «Относительный пик» показывает
форму каждой карты независимо от её силы; «Абсолютный 0–1» позволяет
сравнивать силу отклика разных каналов. Кружки отмечают локальные пики
с адаптивным порогом до 0.02; точное значение видно рядом с числом пиков.
Подпись «30+» означает, что показаны первые 30.

На этой машине `data/keypoints.npz` восстановлен из истории Git и игнорируется
Git. Его ID и размеченные координаты совпадают с сохранённым OOF. Настоящий
`fold0.pt` скачан из папки команды в Google Drive и проверен на MPS: он
содержит 29 каналов, а для фолда 0 доступны 49 отложенных кадров. Чекпоинт
загружается через `torch.load(weights_only=True)` с явным разрешением типов
NumPy, использованных при сохранении имён точек.

Скачанные веса лежат отдельно от рабочего `runs/keypoints/`, чтобы сервис
случайно не подхватил их как веса текущей модели. Вместе с ними сохранены
соответствующие пороги видимости.

Скачанные веса и локальный `runs/keypoints/oof.npz` относятся к **разным
прогонам**. В `fold0.pt` записана медиана ошибки 2.72 мм; по локальному OOF
этого фолда получается 1.32 мм. OOF из папки Drive также отличается от
локального. Просмотрщик показывает предупреждение об этом. Для оценки
гипотез относительно текущих локальных метрик нужны соответствующие им веса;
карты скачанного чекпоинта можно изучать как отдельный прогон.
