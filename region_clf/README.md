# Классификатор области DXA-снимка: `lh` / `rh` / `spine`

Определяет по одному снимку денситометрии, что на нём: левое бедро (`lh`),
правое бедро (`rh`) или поясничный отдел позвоночника (`spine`).

## Место в конвейере

Классификатор — **первое, что происходит со снимком**. Он получает кадр до
всякой разметки и решает, какой набор критериев качества к нему применять
(позвоночник — положение/ось/артефакты, бедро — ротация/ROI). Отсюда три
требования, которым подчинён весь код:

1. **Никакого контекста.** На вход — только пиксели. Ни `разметка.xlsx`, ни
   структура папок исследования, ни имена файлов, ни соседние кадры не
   используются: во время работы конвейера ничего этого ещё нет.
   Проверено прогоном по 252 кадрам, вынесенным в плоскую папку со случайными
   именами и запущенным из чужого рабочего каталога — 252/252.
2. **Разметка — только источник проверки, а не признак.** `разметка.xlsx`
   использовалась один раз, чтобы сверить построенный эталон; в `features.py`
   и `predict.py` её нет ни в каком виде.
3. **Фильтр на входе.** До классификатора снимок никто не проверяет, поэтому
   отбраковка мусора — его обязанность (см. «Отказ от классификации»).

В исходных DICOM нет ни `BodyPartExamined`, ни `Laterality`, ни `ViewPosition`,
ни `PixelSpacing` — все эти теги пустые, а `SeriesDescription` у всех кадров
одинаковый («Изображения DXA»). Внутри исследования лежат 3–29 файлов без
указания области, поэтому определять её приходится по самому изображению.

## Использование

```bash
python -m region_clf.predict снимок.dcm                 # один файл
python -m region_clf.predict путь/к/исследованию        # папка, рекурсивно
python -m region_clf.predict папка --csv out.csv        # выгрузка в CSV
python -m region_clf.predict снимок.dcm --json          # JSON
python -m region_clf.predict папка --strict             # непринятым кадрам ставить unknown
```

```
файл         область   увер.  новизна  статус
CR000000.dcm spine     1.000    0.263  ok
CR000001.dcm rh        1.000    0.213  ok
CR000002.dcm lh        1.000    0.340  ok

файл      область   увер.  новизна  статус
noise.png spine     1.000    2.829  низкий контраст

всего 1: lh=0, rh=0, spine=1; не принято: 1
```

Из кода:

```python
from region_clf import RegionClassifier

clf = RegionClassifier()
clf.predict('снимок.dcm')                  # 'lh'
clf.predict_proba('снимок.dcm')            # {'lh': 0.999, 'rh': 0.0, 'spine': 0.001}
clf.classify('снимок.dcm')                 # полный результат, включая отказ
clf.predict_batch(['a.dcm', 'b.dcm'])      # пачкой
clf.predict(pixel_array)                   # можно и готовый numpy-массив
```

`classify()` и `predict_batch()` возвращают словарь с полями `label`,
`label_ru`, `confidence`, `novelty`, **`accepted`** и `reason`. Конвейер должен
смотреть на `accepted`: кадр с `accepted=False` нельзя отправлять на разметку —
его место в ручном разборе. `predict()` всегда возвращает лучшую из трёх
гипотез и фильтр не применяет.

Принимаются `.dcm` и обычные изображения (`.png`, `.jpg`, `.tif`).
Зависимости: `pydicom`, `numpy`, `pandas`, `scikit-learn`, `pillow`, `joblib`.

## Как получена разметка

Готовой разметки области не было, эталон построен в три шага:

1. **Эвристика.** Ширина кадра ≥ 300 px — позвоночник, 280/248 px — бедро.
   Сторона бедра: `PatientOrientation = [L, F]`, то есть левая половина кадра —
   правая сторона пациента; таз и головка бедра дают яркую верхнюю треть со
   стороны средней линии, поэтому яркая левая верхняя треть = **левое** бедро.
2. **Ручная проверка.** Все 252 уникальных кадра просмотрены контактными
   листами по классам; ошибок эвристики не найдено, включая 3 кадра с
   эндопротезами.
3. **Сверка с `разметка.xlsx`.** Набор найденных областей против набора
   областей, размеченных экспертом (какие столбцы критериев заполнены):
   совпало 98/100. Оба расхождения — эндопротезы («правое бедро
   эндопротезирования», «эндопротезирования ТБС»), которые эксперт не оценивал,
   но снимок в исследовании есть.

Эталон лежит в [labels.csv](labels.csv) (252 строки: `rel_path`, `study`,
`px_hash`, `label`), пересобирается через `python -m region_clf.make_labels`.
В 499 файлах каждый кадр продублирован 1–3 раза — дубликаты (одинаковые
пиксели) схлопнуты, иначе одни и те же снимки попадали бы и в обучение, и в
контроль.

## Модель

| Этап | Что делается |
|---|---|
| Чтение | `pydicom`, VOI LUT, разворот MONOCHROME1 |
| Нормализация | растяжка по перцентилям 1–99 → `[0,1]`, ресайз до 64×64 |
| Признаки | 32×32 пикселя (1024) + гистограммы ориентаций градиента 8×8×6 (384) = **1408** |
| Классификатор | `StandardScaler` + `LogisticRegression(C=1)` |
| Аугментация | зеркальное отражение (`lh`↔`rh`, `spine`→`spine`) + 3 копии с поворотом ±8°, масштабом ±10%, сдвигом ±7%, гаммой |

Обучение — 5 секунд, модель весит 50 КБ.

Два решения, которые стоит знать при доработке:

- **Размер кадра в признаки не входит.** Формально ширина 300 px даёт
  позвоночник со 100% точностью, но это свойство конкретного аппарата
  (GE Lunar Prodigy Advance, все 100 исследований сняты на нём). Модель
  работает только по содержимому изображения, чтобы не развалиться на другом
  денситометре.
- **Зеркальная аугментация** не просто удваивает выборку, а задаёт симметрию
  задачи: отражённое левое бедро обязано классифицироваться как правое. Это
  проверяется тестом.

## Отказ от классификации

Модель обязана выдать одну из трёх меток, а фильтра перед ней нет. Проверка
показала, насколько это опасно: **на чистом шуме модель выдаёт `spine` с
уверенностью 1.000**, на фрагменте бедра — `rh` с 1.000. Уверенность как
признак «своего» кадра бесполезна, поэтому на вход поставлены три проверки:

| Проверка | Что ловит | Как устроена |
|---|---|---|
| Контраст | пустой, засвеченный, шумовой кадр | разброс яркости ниже половины самого тусклого обучающего кадра |
| Новизна | кадр не похож на DXA | ошибка PCA-реконструкции признаков (20 компонент) выше порога |
| Ориентация | кадр перевёрнут сверху вниз | отдельный линейный классификатор «норма против переворота» |

Порог новизны откалиброван **out-of-fold**: PCA обучается на train-фолде и
оценивает отложенные кадры. Порог поставлен на 99-м перцентиле — то есть
1.2% валидных кадров уйдёт на ручную проверку, и это осознанная плата.

Третья проверка появилась не сразу: детектор новизны ловил перевёрнутый кадр
только в 17% случаев (это же всё ещё похожая на DXA картинка), а модель выдавала
на нём уверенную и **неверную сторону** — вертикальный переворот меняет ту самую
яркостную асимметрию таза, по которой различаются `lh` и `rh`. Отдельный
классификатор ориентации решает это: обучающие примеры для него берутся из тех
же кадров бесплатно, accuracy 0.998 на кросс-валидации по исследованиям.

Доля пойманного, замеренная на всех 252 кадрах (каждый тип искажения применён к
каждому кадру):

| Чужой вход | Поймано |
|---|---|
| поворот на 90° | 100% |
| перевёрнут сверху вниз | 100% |
| фрагмент кадра (1/4) | 100% |
| инверсия яркости | 100% |
| чистый шум / пустой кадр | 100% |
| сильный шум поверх снимка | 98% |
| **свои 499 файлов** | **отклонено 0** |

## Результаты

Оценка — `StratifiedGroupKFold(5)` с группировкой **по исследованию**: кадры
одного пациента не попадают одновременно в обучение и в контроль.

| Проверка | Результат |
|---|---|
| Кросс-валидация, 252 уникальных кадра | **accuracy 1.000** (252/252), precision/recall = 1.000 по всем трём классам |
| Прогон обученной модели по всем 499 файлам | 499/499, минимальная уверенность 0.998 |
| Без контекста: плоская папка, случайные имена | 252/252 |
| Устойчивость: поворот ±8°, масштаб ±10%, сдвиг ±7%, гамма 0.8–1.25, шум | **accuracy 0.981** |
| Проверка ориентации (норма против переворота) | accuracy 0.998 |

Как выбиралась модель: на чистых данных логистическая регрессия, линейный SVM
и градиентный бустинг неразличимы (0–1 ошибка из 252), выбирать по такой
разнице нельзя. Разделил стресс-тест на искажённых кадрах — там бустинг падает
до 0.71–0.78, линейные модели держат 0.95–0.97. Обрезка фона по профилю
яркости (`features._crop_content`) тоже проверялась и выигрыша не дала —
оставлена выключенной, но доступна параметром.

Воспроизведение:

```bash
python -m region_clf.train --stress        # CV + стресс-тест + сохранение модели
python -m region_clf.test_region_clf       # прогон по всем 499 файлам + проверка симметрии
```

## Ограничения

- Обучено на 100 исследованиях **одного** аппарата GE Lunar Prodigy Advance.
  На снимках другого производителя точность не проверялась; при появлении
  таких данных модель стоит переобучить — это 5 секунд.
- **Фильтр чужих кадров проверен на суррогатах, а не на настоящих чужих
  снимках.** Предплечья и whole body в наборе нет вообще, поэтому поведение на
  них неизвестно — это самый вероятный реальный чужой вход, и он не проверен.
  Замеренные 98–100% относятся к искажениям своих же кадров. Как только
  появятся настоящие снимки других областей, их надо прогнать через фильтр и,
  если он их пропускает, добавить четвёртый класс «прочее».
- Классов ровно три, и `predict()` всегда возвращает один из них. Отказ живёт
  отдельно — в поле `accepted`; конвейер обязан его читать, иначе фильтра для
  него как бы нет.
- Эндопротезы (3 кадра) классифицируются верно, но их слишком мало, чтобы
  утверждать это статистически.
- Разметка эталона построена мной по изображениям и сверена с таблицей
  эксперта на уровне набора областей; независимой поштучной разметки врача для
  `lh`/`rh` не существовало.
