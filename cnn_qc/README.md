# Нейросетевое второе мнение: `cnn_qc`

Ротация бедра и посторонние предметы на снимке позвоночника — два критерия,
где геометрия упирается в разрешение. Выступ малого вертела отличает норму от
ротации примерно на 2 мм при ширине диафиза 35 мм, а посторонний предмет
бывает и не ярким, и не вытянутым. Здесь к измерению добавлена сверточная сеть,
которая смотрит на весь кадр в исходном разрешении.

Сеть не заменяет измерение. Вердикт выносит **свод**: логистическая регрессия
по двум признакам — логиту сети и геометрическому скору критерия (выход
площади выступа за коридор нормы, счёт white top-hat). Измерение остаётся в
отчёте, а если сеть и геометрия расходятся, кадр получает флаг
`*:cnn_vs_geometry_disagree` и низкую уверенность.

## Модель

| | |
|---|---|
| сеть | ResNet-34, энкодер предобучен на ImageNet, GAP → линейный слой → логит |
| вход | весь кадр: яркость по перцентилям 0.5–99.5, правое бедро отражено в левое, длинная сторона → 320 px без искажения пропорций (`preprocess.py`) |
| обучение | 40 эпох, AdamW 2e-4, one-cycle, батч 16, вес положительного класса = доля отрицательных, аугментации: поворот ±8°, масштаб ±8 %, сдвиг ±6 %, яркость и контраст ±15 %, для позвоночника — отражение |
| поставка | ансамбль из 3 моделей (сиды 0, 1, 2), ONNX с весами fp16 (3 × 42.6 МБ), onnxruntime на CPU в один поток |
| объяснение | карта активации класса (CAM) — она же выход ONNX-модели: логит = среднее по карте. В оверлее — оранжевым поверх снимка |
| свод | `p = σ(a · logit(p_сети) + b · геометрия + c)`, порог — доля нарушений в обучающей выборке |

Предобработка — одна numpy-функция для обучения и сервиса, чтобы сеть видела в
работе ровно те пиксели, на которых училась. Расхождение ONNX с torch на всех
обучающих кадрах записано в `meta.json` (`max_abs_diff_vs_torch`, до 3·10⁻³).

## Как оценено

Всё — out-of-fold по `folds.csv` (группа — исследование). Для каждого сида
пять моделей учатся на четырёх фолдах и предсказывают пятый; OOF ансамбля —
среднее трёх сидов. На этих предсказаниях подбираются свод и порог.

| | ротация, 36 из 150 | посторонние предметы, 17 из 99 |
|---|---|---|
| геометрия, ROC-AUC | 0.68 [0.55–0.80] | 0.79 [0.64–0.92] |
| сеть, одна модель (3 сида), ROC-AUC | 0.76 / 0.77 / 0.78 | 0.73 / 0.73 / 0.83 |
| сеть, ансамбль 3 сидов, ROC-AUC | 0.80 [0.70–0.89] | 0.78 [0.62–0.93] |
| **свод, ROC-AUC** | **0.82 [0.72–0.90]** | **0.82 [0.68–0.94]** |
| свод, PR-AUC | 0.65 (геометрия 0.47) | 0.61 (геометрия 0.55) |
| **вердикт, вложенная оценка**: чувств. / специф. / F1 | 0.67 / 0.76 / **0.55** | 0.65 / 0.91 / **0.63** |
| геометрия, OOF: чувств. / специф. / F1 | 0.63 / 0.70 / 0.48 | 0.53 / 0.94 / 0.58 |

«Вложенная оценка» — строгая: для каждого фолда свод и порог подобраны на
остальных четырёх, сеть этот фолд тоже не видела. Её чувствительность,
специфичность и F1 честные. Её ROC-AUC ниже (0.74 и 0.78), потому что
вероятности пяти разных сводов, склеенные в один ряд, ранжируются хуже любого
из них; для ранжирования показан свод с тремя коэффициентами по всем OOF.

### Что проверялось и не вошло

- **Одна модель вместо ансамбля.** ROC-AUC ротации по сидам 0.76–0.78,
  артефактов — 0.73–0.83: на 17–36 положительных примерах результат заметно
  зависит от сида. Среднее трёх стабильнее.
- **Другие энкодеры** (ротация, 3 сида, OOF ROC-AUC): ResNet-18 — 0.76,
  EfficientNet-B0 — 0.73, ResNet-34 — 0.78. Размер входа 256 px — 0.77,
  384 px — не лучше 320.
- **Порог по максимуму F1.** Во вложенной оценке порог, найденный на четырёх
  фолдах, плохо переносится на пятый: F1 ротации 0.48 против 0.55 у правила
  «доля нарушений». Правило одно для обоих критериев и без параметров.
- **Вердикт по одной сети без геометрии.** Для ротации вложенный F1 0.59, для
  артефактов 0.56 против 0.63 у свода. Оставлен свод: он лучше в сумме и
  сохраняет в вердикте измерение, которое оператор проверяет глазами.
- **Признаки по ключевым точкам** для ротации (длина шейки, положение малого
  вертела относительно диафиза, шеечно-диафизарный угол): по OOF-точкам
  ROC-AUC не выше 0.66.

## Использование

```python
from cnn_qc import CnnQC
cnn = CnnQC()
r = cnn.assess('rotation', px, 'lh', geometry=12.5)   # geometry — выход за коридор, мм²
r['p_cnn'], r['probability'], r['violated'], r['heatmap']
```

В сервисе подключается автоматически (`service/pipeline.py`); выключить —
`--no-cnn` у CLI или `DXA_QC_CNN=0` у API. Нет onnxruntime или весов — кадр
считается геометрией, причина уходит во флаг `cnn:unavailable(...)`.

## Обучение

```bash
pip install -r requirements-train.txt           # torch, torchvision, onnx
python -m cnn_qc.train --criterion rotation     # ~6 мин на GPU: OOF 5 фолдов × 3 сида + ансамбль
python -m cnn_qc.train --criterion artifacts
python -m cnn_qc.train --criterion rotation --calibrate-only   # только свод и порог по oof.csv
```

Геометрические скоры берутся из `hip_rotation/measurements.csv` и
`spine_qc/measurements.csv` — сначала калибровка геометрии
(`python -m hip_rotation.calibrate`, `python -m spine_qc.calibrate`). Обучение
детерминировано: сиды, детерминированные алгоритмы cuDNN, фиксированный
порядок кадров; повторный запуск на той же машине даёт те же OOF-вероятности.

## Файлы

| файл | назначение |
|---|---|
| `preprocess.py` | кадр → вход сети (общая для обучения и сервиса) |
| `train.py` | OOF, свод, порог, итоговый ансамбль, экспорт в ONNX |
| `predict.py` | инференс onnxruntime, CAM, свод, OOF-режим для `service.evaluate` |
| `<критерий>/model_{0,1,2}.onnx` | веса ансамбля |
| `<критерий>/meta.json` | рецепт, свод, порог, метрики OOF |
| `<критерий>/oof.csv` | OOF-вероятности по кадрам: по сидам, ансамбль, свод, вложенный вердикт |
